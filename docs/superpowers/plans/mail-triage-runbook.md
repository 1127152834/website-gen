# 邮件预审灰度、停用与恢复 Runbook

## 不可跳过的边界

- 生产默认保持 **OFF**。本轮只证明离线 fixture；真实 IMAP/SMTP、模型兼容性、生产出站策略和准确性均未验证。
- 邮件正文、收件人、密钥不得写入运行日志或验收统计。邮件中的 URL 永不打开。
- 未完成用户授权的真实人工标注 100 封评估前，状态必须记为 `NOT_QUALIFIED`，不得批准自动通知分流。
- schema 向前兼容；回滚代码时不自动删除表，也不以旧数据库覆盖恢复后新增的真实邮件或人工记录。
- `/mail/notifications` 是通过当前 tuple 的真实资格门与抽查门槛的**通知邮件**；`/mail/reminders` 只是本地跟进提醒。两者不得互相替代。
- 普通收件箱的标签、摘要、证据和更正能力必须绑定当前缓存读取身份；来源世代变化时隐藏注释并停止证据/更正，不得回退触发同步或模型调用。
- 选择申请事项回复时必须携带完整 reader capability，并在创建回执和 SMTP 前重新核验 case/source/version/mailbox/folder/UIDVALIDITY/UID；普通未绑定事项的旧回复保持兼容。

## 灰度顺序与退出条件

| 阶段 | 动作 | 进入/退出条件 | 立即止损 |
|---|---|---|---|
| 0. OFF | 保持预审关闭、无授权邮箱、无模型正文出站 | 旧 `/mail/inbox` 阅读、翻译、原文回复和人工发送仍可用 | 保持关闭；调查任何预审作业即为异常 |
| 1. 单邮箱 fake | 管理员仅在隔离环境配置一个 fixture 邮箱、专用 `mail_triage` Key 与 fake transport | B01–B62、targeted test、离线 browser smoke 全绿；禁止外连计数为 0 | 关闭预审并递增 epoch；确认在途作业已取消 |
| 2. 只建议 | 仅对一个明确勾选邮箱启用 `suggest_only` | 预算/范围/来源/世代检查通过；不自动发信、删信、归档或改已读 | 关闭设置；保留待确认队列和审计记录 |
| 3. 真实人工 100 | 由用户另行授权脱敏真实邮件和人工真值；五组各 20 封 | **本轮未完成：`NOT_QUALIFIED`**。须绑定当前模型/Key/规则/schema tuple，报告可复核 | 不得用合成 fixture 代替，不得批准通知分流 |
| 4. 逐邮箱建议 | 逐个邮箱显式加入 scope；未来新增邮箱默认不授权 | 每个邮箱单独观察失败率、预算、漏待办；旧 reader 持续可用 | 从 scope 移除该邮箱并递增 epoch |
| 5. 资格门 | 只有当前 tuple 的真实报告合格且人工批准，才允许通知邮件进入安全列表 | 审批、报告 hash、抽查边界均为当前版本；任何 missed action 立即暂停，并复核上个连续通过边界后的全部通知位置（含原未抽样位置） | 撤销批准/关闭功能；逐项复核全部尾部位置，保留原 sampled 标记和判定历史 |

## 一致性备份与恢复演练

1. 停止应用接收写入，等待 workspace、worker、SMTP 和模型在途任务 drain；确认进程已关闭数据库连接。
2. 同时备份管理库和每个用户库。对已关闭的 SQLite 使用 `VACUUM INTO '<absolute-backup-path>'` 或 SQLite backup API；**不得复制活跃 WAL 下的单一 `.sqlite` 文件冒充备份**。
3. 对每个备份记录绝对路径、SHA-256、文件大小和创建时间；密钥材料单独按既有密钥流程保管，不写进报告。
4. 恢复到另一独立临时根，绝不覆盖原目录。用相同主密钥启动隔离实例，禁止公网出站。
5. 逐库执行 `PRAGMA integrity_check`（必须为 `ok`）和 `PRAGMA foreign_key_check`（必须 0 行）。
6. 读取并核对：原用户身份、邮箱 address/remote/order 绑定及密文存在性、专用 `mail_triage` 模型绑定、预审设置、三列申请、缓存 reader。进行一次零真实网络的登录/RPC 基础读取。
7. 记录备份与恢复文件 hash。SQLite 重写可能改变字节 hash；完整性、外键和业务绑定读取是必要的语义校验。
8. 删除临时恢复根前解析绝对路径并确认它位于本次创建的临时根；验收截图、JSON、SQLite 备份和 hash 清单必须位于独立证据目录，不随 fixture 清理。

## 运行回滚优先级

1. **最小止损：**关闭预审，递增 config epoch，撤销租约并尝试 abort；已发送给模型的内容不能承诺撤回。
2. **误判补偿：**用人工纠正/撤销事件修复，保留旧评估审计；不要整库回滚。
3. **代码回滚：**只恢复 Task16 拥有且 hash 未被并行修改的文件；保留兼容 schema。
4. **迁移/数据故障：**维持停写，先在独立路径完成上述恢复演练，再由人工决定是否切换；恢复后重新检查邮箱绑定、来源隔离、外键和基础读信。

## 上线前仍需单独授权与验证

- 真实人工标注准确性、真实模型/SDK兼容性和供应商数据处理政策。
- 真实 IMAP IDLE/轮询、SMTP/append、Hostinger inventory 与凭据轮换。
- 生产防火墙/代理/egress、部署恢复时间、告警和运维值守。
- 每个生产邮箱的 owner、scope、预算、退出标准和回滚负责人。
