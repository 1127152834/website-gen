# 一期原型：按模块阅读

这套系统是一支业务团队的**内部工作台**：把客户资料、企业办理结果、网站建设、商业邮箱和支付平台申请放在一起，减少来回找表格、找图片、找邮件的时间。

这里的“客户”是你们服务的美国个人；这里的“用户”是登录系统的工作人员和管理员。**客户不登录这个系统。** 客户把资料交给团队，团队录入、核对、办理并跟进结果；缺少资料时，再联系客户补充。

> 这是原型设计阅读材料，不是已经上线的操作手册。图片展示预期页面和示例状态，不能点击其中的按钮；本文中的故事和图片数据均为虚构示例。文字中说“打开、保存、提交”是在解释将来的使用方式，不表示已经执行了真实操作。

## 第一次看，先了解这条业务线

以新客户 Alex 为例：

1. **先有驾照，再建档。** 员工上传驾照正面，核对识别出来的信息，再录入客户提供的其他资料。
2. **企业在系统外申请。** 员工在客户档案中记录办理状态；完成后补齐企业资料、企业文件和 EIN。
3. **准备并建立网站。** 企业资料和 EIN 齐备后，可为一个客户建站，也可把多个客户放进同一批次。每家企业仍只对应一个网站。
4. **整理银行与补充证明，检查资料。** 客户提供银行信息和文件，团队录入；AI 检查是辅助工具，是否继续由人决定。
5. **指定本次申请负责人，申请支付平台。** 系统记录本次申请和当时的资料；真正的平台申请仍由负责人在系统外完成。
6. **通过商业邮箱跟进，记录结果。** 根据平台邮件处理明确要求。首个有效网关获批后，客户在系统中的业务就算完成；后续网关申请另记。

步骤 3、4 中的准备工作可以按实际情况穿插进行，不必等一个模块所有页面都用完才进入下一模块。系统不负责后续代运营，也不把付款测试列为这期流程。

## 新用户先记住的六件事

- **一个客户、一家企业、一个网站、一个商业邮箱。** 可以有多次网关申请记录，但同一客户同时只能有一个正在进行的申请。
- **操作人不是申请负责人。** 操作人说明当前这项资料是谁最后成功填写或修改的；申请负责人说明这一次网关申请由谁跟进。准备资料不必先指定客户负责人。
- **当前资料不是历史申请资料。** “申请时资料”是在开始申请时留存的那一份。后来改客户档案，不会悄悄把过去那份也改掉。
- **驾照地址不一定是当前住址。** 两个地址分开记录，不因不同就自动认定资料有问题。
- **AI 是辅助，不是审批机构。** 资料检查有问题不代表一定被拒；没有发现问题也不代表一定获批。邮件判断要能找到对应原文，有误可以纠正。
- **“已发送”“网站已上线”“网关已获批”是三个不同结果。** 回复了准备进度，不等于文件已经交齐；网站能打开，也不等于支付平台已批准。

## 故事：新同事接手 Alex 的业务

小周刚加入团队。客户 Alex 发来驾照和联系方式，小周先去“客户档案”上传驾照，核对姓名和驾照信息，并单独填写客户现在的住址。

几天后，同事在系统外办好了企业，把企业文件和 EIN 填回档案。小周进入“网站建设”，选择 Alex，核对经营资料、网站配置和启动范围，再查看建站结果。需要网站地址或商业邮箱时，不必再到聊天记录里反复寻找。

准备申请支付平台时，由李敏作为**这次申请的负责人**。平台发来补充证明的邮件，李敏在“邮箱”读原文，再到对应申请查看要求和准备资料。她回复“正在准备”时，不会把这条要求记成“已全部提交”。

首个申请有效获批后，Alex 在系统中显示完成。如果后来发现是误判，团队要纠正申请状态，系统中的客户状态也要重新按有效获批记录判断。整个故事中，客户不需要登录系统。

## 一些词，先用白话解释

| 名称 | 这里指什么 |
|---|---|
| EIN | 美国企业使用的税务识别号码；在本系统里属于企业资料，不是客户的 SSN |
| 支付网关 | 网站收款所使用的支付平台，例如 Stripe、PayPal；本期管理的是申请资料和申请结果 |
| 商业邮箱 | 这个客户企业使用的邮箱，也是与支付平台沟通的邮箱 |
| 批次 | 一次放在一起启动、查看进度的一组建站任务；每个客户的网站仍然独立 |
| 申请定稿 | 开始本次申请时留存的资料版本，用来核对当时采用了什么，不是所有编辑过程的历史 |
| 凭据 | 连接其他服务所需的登录或授权信息；保存了凭据不等于连接已经成功 |
| 同步 | 把服务中的信息更新到本系统里；不等于自动回复邮件或完成业务 |
| Hostinger | 本项目接入的建站与域名等资源服务；在资源模块中查看其账号和关联资源 |
| Grist | 团队使用的外部协作表格工具；工作台提供入口，不把它当成客户建档导入工具 |
| CJ | 本项目接入的商品资料服务；读取商品资料不等于已向供货方下单 |
| SMTP 接受 | 发信服务接收了这次发送请求；不保证邮件已经送到收件人，更不等于支付平台获批 |
| 弹窗／侧边展开区 | 页面中临时出现的小窗口／从侧面打开的区域，用来确认或编辑，不是额外的业务阶段 |

## 怎样看这些文件

每个模块文件夹中都有：

- **模块介绍.md**：先读用途、流程、故事和注意事项。
- **页面目录.md**：按使用顺序列出所有图片，点击中文名称即可打开。
- **中文名称的 PNG 图片**：例如“客户建档-上传驾照正面”“邮件回复-发送前确认”。编号只用于排序，不是必须照着执行的步骤。

同一功能的多个状态单独命名，例如“正在加载”“读取失败”“提交结果暂不确定”。这些是不同情境下的设计示例，不是要求你把错误流程再操作一遍。跨模块复用的入口在页面目录中直接链接，不重复制造一套功能。

本阅读版按 **9 个模块**整理，放入 **180 个中文命名的图片文件**。它们来自 **179 张不同的原图**：“通用导航”借用了客户上传页作为示例，在两个模块中各保留一份便于单独阅读。另有 11 个复用入口通过链接指向相应页面，不算新增图片。

本次只复制和重命名图片文件，没有重画图片内容。旧版、原始文件名、历史修订及复核证据都保留在[原设计档案](../full-system-prototype-20261017/README.md)。本期仍是静态原型，真实交互、权限执行、AI 效果和第三方连接要在后续开发中实现并验证。

面向维护人员的对应关系见[页面映射](页面映射.json)和[图片复制校验](图片复制校验.json)，检查与回退方式见[整理说明](整理校验与回退说明.md)；普通使用者不需要阅读这些文件。
