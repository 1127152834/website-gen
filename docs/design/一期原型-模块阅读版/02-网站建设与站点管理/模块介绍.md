# 网站建设与站点管理

> 这里描述静态原型的使用路径。图片不可操作，不代表功能已上线；客户、企业、域名、邮箱、进度和结果均为虚构示例。

**一句话用途：**从左侧“网站”分组选择客户并完成三步建站，随后在“批次”和“站点”中跟踪每个网站、处理失败、维护内容并完成上线前复核。

## 先理解它在项目中的位置

系统按“一位客户、一家企业、一个网站”组织建站。客户不登录，内部员工负责选择、确认和交接。企业资料与 EIN 必须先在客户档案中齐备；网站公开的企业法定名称和地址来自企业档案，联系电话来自客户个人电话，商业邮箱用于网站和业务邮件。品牌名可以与企业法定名称不同。

当前客户档案、本次建站配置、已经发布的网站内容彼此独立。修改客户档案不会自动改写已发布内容；恢复网站变更也不会改客户档案或网关申请定稿。**网站建成、网站上线、网关获批是三个不同标志。**

## 开始前准备什么

1. 在客户档案确认企业资料和 EIN 齐备，且客户没有现有网站。选择客户侧栏会直接标出不符合条件的行；已有网站时应点“查看站点”，不要重复新建。
2. 准备该客户自己的可用域名和同域名商业邮箱。第二步会分别读取域名和邮箱资源，不能拿其他客户的资源顶替。
3. 准备经营参数：订单处理工作日、运输时效、店铺品牌、商品品类、商品数量，以及需要时填写的售价区间。
4. 确认模型、商品资料和 Hostinger 等相关服务已经由管理员配置。启动确认页明确提示建站会调用这些服务，可能产生模型费用。

CSV 只导入**站点配置**，不能导入客户、创建企业或绕过第一步资料核对。

## 三步建站怎么走

### 第一步：客户与经营资料

点“选择客户”，只加入企业资料与 EIN 齐备、尚未建站的客户。回到主表后，为每位客户填写订单处理和运输工作日；点“查看资料”或下方档案摘要，核对企业名称、地址、个人联系电话和商业邮箱。多客户时每行独立，移出某行只影响本次名单，不删除客户。

### 第二步：站点配置

每行依次选择域名、同域名商业邮箱，填写店铺品牌、商品品类和详细参数。域名或邮箱“读取失败”时点该行“重试读取”；检查未通过前，“下一步：确认启动”不可用。若读取成功但“暂无可用域名/邮箱”，按画面入口去“账号与域名管理”或 hPanel 准备资源，返回后点“刷新”。这两种状态不能混写成客户资料错误。

### 第三步：确认启动

逐行复核域名、邮箱、品牌、品类、数量、价格、处理和运输时效；勾选“我已核对配置并知悉上述说明”，再点“确认并开始建站”。必要条件弹窗会列出具体客户和问题，可“查看客户档案”或“返回站点配置”。问题未修复前不会提交任何任务。

若出现“提交结果未知”，先点“核验提交结果”或“查看已有任务”；请求可能已经发出，不能直接再次提交。确认成功后，到“批次”看每个站点自己的状态。

## 提交后怎样判断进度和完成

- **建站中：**批次详情显示当前步骤，例如生成页面。
- **等待外部服务：**说明任务在等待商品、主机等外部返回，不等同失败。
- **失败：**在站点“概况”点“查看完整记录”或“查看步骤与日志”，确认失败步骤；“确认重试”只从可恢复步骤继续，不会创建第二位客户或第二个网站。点确认不代表恢复成功，仍要回执行记录核对。
- **建成：**站点列表的“建站状态”显示“建成”。这只表示网站生成完成。
- **已上线：**“上线状态”单独显示“已上线”。站点可能已建成但仍处于“维护中”；只有明确确认上线并看到上线标志，才可交接为已上线。网关结果仍到网关申请模块查看。

## 建成后常用的五个页签

- **概况：**看执行步骤、当前失败点和日志。
- **AI 对话：**对话会直接修改网站，并生成可查看的变更记录；开始新对话不会撤销已经应用的修改。
- **邮箱与交易发信：**用于网站订单通知等交易邮件，不是客服收件箱。可检查 MX、SPF、DKIM 和 SMTP，修复确认只使用已保存凭据，不自动重置密码，也不会顺便发送测试邮件。测试邮件只验证发信；结果未知时先“核验发送结果”，不要连续重发。
- **变更记录：**先“查看详情”再恢复。恢复只覆盖该次网站变更，不修改客户档案或网关定稿；存在后续修改时会被阻止。
- **网站复核：**查看问题证据，将“可修复”和“需人工处理”分开。自动修复完成后仍需重新复核；关闭进度面板不等于取消后台任务，人工项也不会自动标为通过。

上线前若最新复核结果读取失败，历史报告只供参考，必须点“重新读取”；没有当前结果时不能按“无问题”上线。即使当前报告仍有未解决项，画面允许在明确勾选知悉后继续上线，但这只针对网站上线，不改变网关审核。

## 可在图中定位的用户故事

李敏从“建站总览”点“新建网站”，在“选择客户”侧栏中勾选三位显示“企业资料与 EIN 已齐、未建站”的客户。第一步填写处理和运输时效；第二步逐行选择域名与商业邮箱；第三步核对清单并启动。提交后，她在“批次详情”看到一位“建站中”、一位“等待外部服务”、一位因“配置 SSL”失败。她只打开失败站点的“步骤与日志”并确认重试。另一站点显示“建成”但“维护中”，她先进入“网站复核”处理可修复项、查看人工项，再决定是否确认上线，没有把建成、上线或网关获批混为一谈。

## 异常处理与交接

- 资源读取失败：保留已填配置，按行重试；暂无资源则去画面给出的资源入口准备后刷新。
- 必要条件未通过：按弹窗定位到客户档案或站点配置，修复后再次确认，不能跳过。
- 提交结果未知：核验已有任务，避免重复建站。
- 修复或恢复部分失败：分别记录成功、失败、未执行和需人工处理项，不说“整体已恢复”。
- 交接时至少写清客户与域名、批次、建站状态、上线状态、当前失败步骤或复核问题、已完成动作和下一步；业务页只记录最后成功操作的操作人，不给客户虚构固定负责人。
