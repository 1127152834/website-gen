# 客户档案与资料

> **设计说明：**本页介绍的是当前一期静态原型，帮助内部员工和管理员理解页面怎么配合使用。图片不可点击，也不代表功能已经上线；真实保存、识别、审核和删除结果仍需在后续系统中验证。

**一句话用途：**把一位客户从“上传驾照建档”到个人、企业、银行、附件、网站和邮箱资料整理到同一份内部档案中，供后续建站与支付网关申请共同使用。

## 在整个项目中的位置

客户档案是后续工作的资料底座。系统按“一位客户、一家企业、一个网站、一个商业邮箱”组织关系，建站和网关申请都从这里读取已经核对的资料。客户不会登录这套系统，也不需要自己在页面中操作。

企业注册本身在系统外办理；这里记录办理状态、结果和相关文件。**EIN 是企业的联邦税号，用来识别企业的税务身份。**企业资料和 EIN 齐全后，才能进入建站流程。

## 谁用、什么时候用

- **资料录入人员：**收到客户驾照和业务资料时建档，核对识别结果并补全信息。
- **内部经办人员：**建站、申请网关或回复资料问题前，回到档案核对当前内容。
- **管理员：**协助处理权限和高风险操作。重复客户、保存冲突并不等于必须交给管理员；经办人先核对事实，不能凭同名自动合并。

以上是工作分工，不是新增权限角色；能否执行具体操作，要以账号权限为准。

准备资料阶段没有固定“客户负责人”。每个字段和每份附件只显示当前最后一次成功操作的操作人；取消、失败或仅查看不会改变操作人，也不会形成一套完整的历史变更记录。

## 使用前准备

1. 准备每位客户的驾照正面图片。无论单张还是批量建档，每一位客户都必须上传。
2. 另请客户提供 SSN、当前住址、电话和个人邮箱；这些信息无法从驾照自动得出。把“驾照上的地址”和“当前居住地址”分开核对，不能用一个地址覆盖另一个。
3. 按实际情况准备企业资料和 EIN。银行信息、近三个月流水和银行介绍信也由客户提供。
4. 证明附件可按需要提供多份，并非全部必填；文件数量也不能说明支付平台已经收妥。文件按用途保存，具体位置见下表，不必找一个总的“材料页”。
5. 如需关联业务资源，先确认要使用的网站和商业邮箱，避免把其他客户的资源接入本档案。

## 新员工先从哪里进入

从侧栏 **“客户”** 进入[客户列表](01-客户列表-搜索与快速查看.png)。已有客户先搜索姓名、企业或域名，选中后右侧只是快速查看；要改资料，点 **“打开完整档案”**。新客户用右上角 **“上传驾照建档”**，单张和多张都走同一个入口。

## 建档：上传、核对、提交是三件事

1. 在[上传页](03-客户建档-上传驾照正面.png)点“选择图片”，上传正面后看每张的上传状态和识别状态。**上传成功、识别完成都还没有创建客户。**识别失败可“重新识别”或对照已上传图片“人工转录”；肉眼也看不清时，请客户补清晰图片，不猜字段。
2. 点“进入人工核对”，在[核对页](04-客户建档-核对驾照识别结果.png)对照中间原图修改右侧候选值，再点 **“确认本项并继续”**。这一步只保存核对结果；当前住址、SSN、电话和邮箱在建档后另填。
3. 遇到[重复线索](06-客户建档-重复驾照或同名客户处理.png)，先辨认是否同一人。“仅关联已有”不改旧字段或驾照图片；需要更新识别字段时选“关联并核对差异”，逐项选择保留当前值或采用识别值；确为不同人可另建，不确定就跳过。保存处理决定返回后，**仍须统一提交**。
4. 点右上角 **“提交已确认项”**，再到[建档结果](05-客户建档-查看建档结果.png)逐项看“已创建／已关联／创建失败／未处理／已跳过”。只有成功结果才表示已写入；“已关联”不是新增一名客户。可从成功行“打开档案”继续，失败和未处理项按各行入口处理，不必重传全部。

## 建档之后，资料放在哪里

在完整档案中按顶部标签进入；下列位置名称与原型页面一致。

| 要办的事 | 去哪里、怎么做 | 怎样核对结果 |
|---|---|---|
| 补个人信息与两个地址 | [个人资料](11-个人资料-基本信息与两个地址.png) → “编辑个人资料” → “保存修改” | 回到资料页检查保存值及对应操作人；驾照只列上传状态，点“查看”才看图 |
| 记录企业办理、填 EIN、存企业文件 | [企业资料](13-企业资料-企业信息与税号.png)：状态用“更新办理状态”，字段用“编辑企业资料”，文件用“上传文件” | **三项分别维护**；状态“已办结”不会自动填 EIN 或生成文件，建站前要逐项核实 |
| 填银行账号、存介绍信与流水 | [银行资料](16-银行资料-账户信息与银行文件.png)：编辑账号信息，另点“上传文件”选类型、选文件并“开始上传” | 逐份上传成功才算保存；两份文件不等于已覆盖要求的三个月，月份要看文件内容 |
| 存库存照片、履行协议等 | 档案“网关申请”标签 → “补充证明”区域 → [当前补充证明](../03-支付网关申请/04-客户网关面板-管理当前补充证明.png) | 这是客户当前文件，未开始申请也可准备；上传不等于发给平台，不回写旧申请定稿 |
| 找网站和商业邮箱 | [网站与邮箱](28-网站与邮箱-查看客户关联.png)：核对关联，已有站点用“打开站点详情”，邮箱用“前往邮箱” | “已关联”只是关系；网站实际信息看“对照网站公开信息”，未读取不算已核对 |
| 请 AI 帮忙检查 | [材料审核](33-资料审核-查看检查结果.png) → 选目标平台 → “开始审核”或“只复核变化项” | 分清“发现问题”“执行失败”“未检查”；查看问题证据，不能只看一个总状态 |
| 查某项资料是谁操作的 | 点字段旁蓝色操作人姓名，或进入[资料操作归属](37-操作人查询-个人资料第1页.png) | 按资料类别、类型或操作人筛选，查看来源和时间，不是完整修改历史 |

**“材料审核”是检查工具，不是材料存放页。**修改资料或换平台后，使用变化项复核；受影响的关联项也需一起检查，不是只检查一个孤立字段。审核只供参考，有问题、未检查或失败时，员工知情并确认后仍可继续申请。

填表时，FN 是名、LN 是姓，ZIP 是邮编；SSN 是客户个人号码，EIN 是企业税号，不要互填。Routing Number 是银行路由号码，不是公户账号，均照客户提供的银行资料录入。日期按 **月／日／年**，例如 04/18/1990；州从下拉列表按缩写和全名选择。

## 这一段做到什么，接下来去哪

- **建档完成：**结果页明确“已创建”或“已关联”，能打开正确档案。不是列表中的“客户已完成”。
- **准备建站：**企业资料、EIN 和企业文件已核对，再交到[网站建设模块](../02-网站建设与站点管理/模块介绍.md)；已有网站先关联，不再新建第二个。
- **准备申请：**核对个人、企业、网站、商业邮箱及客户提供的银行／证明资料，再按[网关申请模块](../03-支付网关申请/模块介绍.md)开始本次记录。只有首个有效网关获批，客户才显示“已完成”。

## 两个具体故事

**故事一：批量建档里有一张模糊驾照。**李敏一次上传了五位客户的驾照正面，其中四张识别成功，一张无法提取字段。她先核对成功的四份，再查看模糊图片：只有肉眼能清楚读出内容时才人工录入；如果仍然看不清，就请客户重新提供清晰图片，不能猜测。已上传的原始驾照会保留，系统不会把“识别失败”误解成“可以不交驾照”。

**故事二：企业地址更新，但旧申请不跟着变。**王芳把客户当前企业地址改为新地址，并替换了对应企业文件。当前档案显示王芳为这些项目的最后操作人；此前网关申请保存的资料定稿仍保持原样，已发布网站内容也不会自动改写。团队可据此决定是否复核相关资料，而不是假定所有地方已经同步。

## 常见误解与失败处理

- **“资料审核通过就等于平台会批准。”**不是。检查只提供参考，最终是否获批由外部平台决定。
- **“可以先手工建客户，以后再补驾照。”**不可以。驾照正面是建档前提；识别失败后仍须对照原图处理，不能跳过驾照。
- **“资料都在一个材料清单里。”**不是。文件跟随个人、企业、银行等对应区域保存，便于理解用途。
- **“操作人就是客户负责人，也能看到完整修改历史。”**不是。准备阶段没有固定负责人；这里只显示各字段或附件当前最后一次成功操作的人。
- **上传或保存结果不确定：**先回到列表或档案核实结果，不要立即重复提交。部分上传失败时只补失败项；保存失败时保留原输入，确认网络和当前记录后再试。
- **多人同时修改：**先查看最新内容，再决定保留哪一版，避免覆盖同事刚保存的资料。
- **删除客户：**这是不可当作日常整理的高风险操作。[确认框](42-删除客户-确认影响范围.png)会列出档案、当前附件、全部申请及定稿、专属案件与待办、实际网站等删除范围；域名保留并解除绑定，商业邮箱和原始邮件保留。在办申请需要额外勾选确认。提交后还要看[执行结果](43-删除客户-查看执行结果.png)：失败步骤可重试，未知步骤先重新核验，不能因档案已消失就认定网站也已删除。

## 当前原型没有展开的入口

驾照反面是可选、可后续补充的资料；现有个人资料图只展示了它的上传状态，编辑侧栏展示的是字段，并未展开反面补传的具体入口。因此本说明不编写一个图中不存在的上传按钮路径；也不要用“重新建档”代替补传。
