# 系统设置

> **原型说明：**本目录展示的是静态界面图片，图片中的开关、保存、测试和确认按钮都不可点击，也不代表配置已经上线、保存成功或连接真实服务。

**一句话用途：**由负责系统设置且有相应权限的内部人员集中配置模型服务、商品资料、邮箱默认参数、Grist、邮件 AI 预审和邮件关联规则，并清楚区分“已填写”“已保存”“已验证”和“已授权”。

## 它在项目中的位置

系统设置为建站、助手、邮件、表格等模块提供共用连接和默认值，但不替代人工判断。“凭据”可理解为连接外部服务所需的登录钥匙或授权信息；长期保存的凭据只显示状态或尾号，新生成的一次性授权值仅在确认流程中短暂显示，不长期回显。原型不包含真实密钥。保存凭据不等于验证成功，更不代表外部服务已批准任何业务。

代表页面：[查看邮件 AI 预审范围与开关](11-邮件AI设置-预审范围与开关.png)

## 谁在什么时候使用

- 负责系统设置且有相应权限的内部人员，在接入或更换外部服务、调整团队默认参数、分配模型用途时使用。
- 邮件 AI 准备启用、范围或模型发生变化、抽查发现遗漏时，由有权审批的内部人员在这里确认或暂停。
- 普通业务员工使用配置产生的结果，不能把演示状态当成真实连通证明。客户不登录此应用。

## 开始前准备

先确认这次要配置哪一项，并从对应服务取得必要信息：模型服务需要协议、Base URL 和 API Key；CJ 需要只读商品资料 Key；Grist 需要 Base URL 和 API Key；邮箱默认参数需要拟用于新建或待验证邮箱的默认密码。邮件 AI 还要先确定专用模型、邮箱范围、每日上限、提醒地址和正文外发同意。不要把示例地址或圆点遮挡的 Key 当作可用配置。

## 一个虚构用户故事

原型中的林悦准备试用邮件预审：设置页要求她先选择专用模型、邮箱范围、每日上限与提醒地址，并确认纯文本正文会发送到哪里；另一张图展示抽查发现遗漏后“预审已暂停”。按画面规定，她下一步应人工复核、确认邮箱范围并“提交重新批准”。这些是设计流程，不表示模型连接、外发或重新批准已经实际发生。

## 常见误区与异常处理

- **误区：保存就是验证成功。**保存只表示系统收到了配置；连接测试、授权批准和具体业务结果各自独立。
- **误区：邮件 AI 开启后会自动处理所有历史邮件。**历史补审要单独预览范围并确认，且 AI 结果必须允许人工抽查和纠正。
- **误区：规则命中就是身份或审批事实。**规则只能缩小候选范围，最终归属和业务状态必须回到原始证据核对。
- **异常：验证失败或网络错误。**保留未验证状态，不回显授权信息，不把失败解释成账号被封。
- **异常：批量操作部分成功。**分别列出成功、失败和稍后重试项，不宣称整体成功或自动恢复。
- **异常：更换地址、模型或范围。**这些变化可能让旧批准不再适用，应重新测试或重新授权，而不是沿用旧状态。
