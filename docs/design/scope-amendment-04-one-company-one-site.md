# 范围调整 04：一客户、一企业、一网站；以建站 UI 优化为主

日期：10/17/2026。依据用户本轮明确纠正。

## 已确认，不再作为待选方案

1. 支持一次为一个客户建站，也支持一次为多个客户分别建站，两者都是本期设计范围。
2. 每个客户对应一家企业，每家企业只对应一个网站；不存在一企业多个网站的业务。
3. 批量是多条独立的“客户—企业—网站”建站项，不共享整批企业资料，不把同一客户复制成多站。
4. 当前建站系统核心功能已经成熟，本轮基于现有功能优化 UI、信息层级和客户关联，不重做核心流水线、不增加无关功能。
5. 本轮仍是先文档、讨论，再画静态原型；没有授权编写或改动应用代码。

## 对旧文档的覆盖

- [第 03 组 v1](F:/projects/website-gen/docs/design/group-03-website-management/design-brief-v1.md)中“先单客户，多客户有需求再做”的建议、Q1 的二选一问题，均被本次决定覆盖。
- 旧清单中“独立建站保留一主体多站”的产品解释不再适用。全局新建网站入口可保留，但与客户入口使用同一套一对一规则，不形成例外。
- [源码证据](F:/projects/website-gen/docs/design/group-03-website-management/source-evidence.md)里的历史数据结构仅是本地实现快照，不是产品应继续支持一企多站的依据。后续实现如何衔接另行处理，本轮不做技术重构。
- 不因为旧 CSV 能导入站点，就恢复客户资料/Grist 导入，也不允许导入路径绕过一对一关系。既有 CSV 的界面适配单独处理，不擅自声称已完成或删除已有能力。

## 不改变

企业资料和 EIN 就绪再为客户新建网站；公开企业名称/地址来自企业档案、电话来自客户个人电话、邮箱使用商业邮箱、品牌可不同于法定名称；材料准备不设客户负责人；操作人系统记录；网站生成/上线与客户获批完成分开。

客户既有网站关联、域名/邮箱规则、客户删除影响范围，以及原有建站、AI 对话、网站复核、变更恢复、交易发信核心能力继续承接。界面具体布局仍待确认，不把本次业务规则确认扩大为整套页面批准。
