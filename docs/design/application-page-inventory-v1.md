- **已有**：当前工作区源码能定位到对应页面或交互；不等于线上可用或真实服务已验收。
- **优化**：保留已有能力，调整组织、展示或交互；具体新增部分会注明。
- **新增**：当前没有对应客户业务界面，需要新设计。有后端基础也不冒充已有页面。

## 1. 设计依据与不能改变的边界

业务依据：[客户办理与材料管理业务结构](F:/projects/website-gen/docs/customer-business-structure-v1.md)，并以用户随后明确的“不要推测下一步”和本轮“先文档、再逐张原型图、暂不代码”覆盖旧稿中的泛化表述。

1. 只有内部员工和管理员使用；客户不登录系统。共享客户资料，每位客户有负责人。
2. 一客户、一企业、一网站、一商业邮箱；网关申请可多次，但正常办理时只能有一个在办。
3. 客户是否完成与当前申请状态分开：首个有效获批即完成；后续申请不抹去完成结果；误判获批被纠正时同步重新判断。
4. 驾照识别结果须人工确认；证件地址、当前住址、企业地址分开。识别失败不等于身份无效，同名不等于同一客户。
5. 企业资料和 EIN 齐备才能启动新建站；关联已有站点不要求重建，也不伪造资料已齐备。
6. 网关外部申请由负责人手动办理，系统只记录开始、进展、证据和结果，不画“自动提交申请”。
7. 材料审核是参考工具。未审核、执行失败、检查中或发现风险，均不能变成禁止申请的理由；单在办限制与操作权限仍须满足。
8. 资料修改后标记相关检查需更新，增量检查只覆盖变更及受影响的关联项。不能把旧结果继续展示成当前全部通过。
9. 不推断客户的“下一步”、具体缺哪个月流水、获批概率或综合完成百分比。文件份数不等于材料齐全。
10. 只有邮件明确提出、且有原文来源的要求，才可显示为本次申请的具体要求；待补件状态本身不能推出缺什么。
11. 删除客户：删除档案、材料、申请等客户记录及实际网站；域名解绑但保留，不改变续费；邮箱及原邮件不处理。不能复用现有“放弃站点”。
12. 不做客户表格导入、材料版本、打包导出、客户归档/暂停、测试付款、银行开户、自动注册企业或后续代运营。原有独立建站、站点 CSV 和 Grist 功能不因此被删除。

### 3.3 网关申请：同一记录，多处入口

| ID | 页面/子页及形态 | 负责什么、主要内容和动作 | 来源与边界 |
| --- | --- | --- | --- |
| G01 | 网关申请列表 | 按客户、负责人、平台和申请状态筛选；看当前和历史申请，进入 G02 | 新增界面；一个客户多次申请会多行，因此必须显式带客户；不能拿它代替一客户一行的 C01 |
| G02 | 单次申请详情／概览 | 客户/企业/网站/商业邮箱、本次平台、开始时间、状态、状态来源、人工记录结果；进入材料和邮件 | 新增业务界面，利用现有邮件案件基础；开始只表示记录人工办理，不代替平台提交 |
| G03 | 申请／邮件与明确要求，G02 页签 | 关联原邮件、原文证据、明确提出的补件或回复要求；逐项记录处理情况，跳到邮箱回复 | 后端已有案件/事件/待办基础，界面待设计；来源不明不造要求，上传材料≠已提交，发信≠平台确认收到 |
| G04 | 申请／状态与纠正记录，G02 页签 | AI 推进、人工作业及纠正的时间、前后值、来源；纠错后客户状态变化 | 新增展示；旧邮件重放不得覆写人工纠正，新邮件可继续推进。终止申请不被旧邮件复活 |

客户档案中的申请详情入口与邮件中的“查看申请”都打开 **同一个 G02**，返回时保留原列表筛选或原邮件位置。不另外建一套只在邮箱里有效的客户获批状态。

**唯一业务主记录（页面层约定）**：网关申请负责本次客户办理的状态、结果和完成联动；邮件事项负责邮件证据归组。未确认、未关联客户的邮件候选事项不算“客户已开始申请”，也不占客户在办名额。负责人开始申请后，将已确认的邮件事项与该申请一对一关联；同一事项不能连接多个客户申请。G02/G03/M07读取同一关联结果，不能各自维护一份互相矛盾的申请状态。底层用何种表结构实现，留到以后技术设计，本轮不决定。

邮件 AI 应用明确获批证据时，要更新这条业务申请并同时重新判断客户完成状态；人工纠错按同一规则回算。来源不清时只进入待确认，不通过“建一个新案件”自动开始第二次网关申请。

## 4. 弹窗、抽屉和展开面板清单

### 4.1 统一使用规则

- **固定速览栏**：C01 的选中客户预览，轻量只读，不因编辑变成另一份档案。
- **抽屉**：保留当前页面上下文的资料编辑、证据详情、关联选择；长内容可滚动。
- **弹窗**：单一确认、短表单、风险说明；长时间执行不让用户一直盯着不可关闭的模态窗。
- **独立页面/步骤**：驾照多文件核对、完整档案和建站向导等复杂操作。
- **展开面板**：任务进展、翻译结果、邮件预审等依附当前对象的内容。

## 5. 必须单独考虑的状态稿

不是每个页面把所有状态都画一遍。通用状态画一套，业务特有状态按下表补图；**这些是待画清单，不是已实现状态**。

| 状态组 | 要展示的情形 | 展示与动作规则 |
| --- | --- | --- |
| 列表读取 | 首次加载、刷新中、无数据、筛选无结果、读取失败、部分区域失败 | 骨架与空状态分开；刷新尽量保留旧内容并标刷新状态；失败给重试，不假装零客户 |
| 详情读取 | 未选中、对象不存在、无权限、部分字段或附件读取失败 | 不展示上一个对象的数据；局部失败不吞掉已读部分 |
| 表单 | 浏览、编辑、未保存、校验错误、保存中、成功、失败、同事已修改 | 不只用 Toast 报错；错误贴近字段/动作；失败保留输入 |
| 上传 | 待上传、上传中、成功、失败、取消、重复候选、格式不支持 | 单文件反馈，不用“一批成功”掩盖部分失败；失败不改变已有文件 |
| 驾照识别 | 排队、识别中、待人工确认、部分字段未知、失败、重复待决定、已确认 | 未确认不能自动建客户；失败可手工补录；不用“身份认证通过”标签 |
| 企业 | 未申请、办理中、待补充、已办结；文件/EIN分别有无 | 建议状态命名待确认；状态不是文件齐备的替代品 |
| 建站 | 排队、执行中、等待外部/配置、失败、部分完成、站点生成完成、上线 | 沿用真实执行状态，显示可用的重试入口；不等于客户完成 |
| 材料审核 | 未检查、检查中、完成、部分完成、失败、取消、需更新；发现项/未检查项 | 允许申请；“运行失败”与“发现问题”完全不同；不用全局通过分数 |
| 网关申请 | 未开始、申请中/审核中、待补件、等待回复、获批、拒绝、撤回/终止 | 具体显示词与已有邮件分类映射，不新增无证据推断；待补件/等待回复仍在办 |
| 申请并发 | 两个入口同时开始、提交期间另一申请已生效、请求结果未知 | 最终只允许一条正常在办；失败方重读并打开已有申请；结果未知先核实，不重复开始 |
| 客户完成 | 尚未完成、首个有效获批、完成后追加申请、唯一获批误判被纠正、另有有效获批 | 同屏展示客户状态和当前申请；不互相覆盖 |
| 邮箱连接 | 未配置、验证中、连接成功、凭据被拒、网络暂不可用、监听关闭、同步中/失败 | 不把所有失败都写“密码错误”；默认密码成功不代表所有邮箱都成功 |
| 邮件正文 | 加载、已读/未读、正文不可用、附件失败、翻译中/失败、译文可用 | 纯文本，原文可回看，附件主动下载；不加载远程图片 |
| 邮件预审 | 未分析、排队/运行、成功、失败、待确认、已纠正；未启用、初始化、额度暂停、配置阻断、审计暂停 | 不能用分析成功表示申请获批；状态更新保留对应邮件依据；预算/配置阻断不是邮件内容有问题 |
| 发信 | 编辑、发送中、已发送、失败、结果未知、发送成功但归档异常 | 不将归档异常说成确定未发送；结果未知先核查，避免一键重复发送 |
| 关联 | 未关联、已有唯一关联、候选被占用、关联目标不可访问、更换影响历史 | 关联不是复制、创建或同步；历史证据不能被新邮箱关联改写 |
| 删除/高风险执行 | 确认前、执行中、部分成功、失败、结果未知、已核验完成 | 逐项显示影响；允许返回查看执行结果；不能把未核验状态标完成 |
| 凭据/AI配置 | 未设置、获取/测试中、测试失败、保存失败、已保存、用途无可用模型 | 保存成功≠能力验证通过；新用途不可用时给配置入口，不假运行 |
| 全局 | 无权限、身份复核中/失败可重试、会话失效、服务异常、网络中断、窄屏 | 真实说明，不以遮罩永久卡住；窄屏切换列表/详情，不挤满多层抽屉 |

## 6. 跨页面业务路径：确保能连起来

### 6.1 建档到企业就绪

C01 → C11 手工建档，或 C12 上传 → C13 人工确认/重复处理 → C14 结果 → C02/C03 → C04 录入外部企业结果和 EIN。

负责人可以在缺少其他资料时先保存档案；SSN、当前住址等由员工之后补。不会在驾照识别完成后自动编造企业或银行资料。

### 6.2 从客户进入现有建站

C07 → 企业资料/EIN前提校验 → W02/W03/W04 → W06/W08 → 返回 C07 查看关联站点。

也允许 C07 → O-C11 关联已有网站。站点执行失败不丢客户档案；解除关联不删除网站。独立建站及站点 CSV 保留为原有工具，不绕过客户发起模式的一客户一站规则。

### 6.3 材料、审核和网关

C06/C05 补资料 → C08 参考检查（允许跳过或知悉问题后继续）→ O-G04 负责人记录开始 → G02 → G03/M03 查邮件、补材料、人工回复 → 获批后更新客户完成。

“补文件到档案”“附件加入待发邮件”“实际点击发送”“平台回应”“申请获批”是五个不同事件，不能用一个完成勾选代替。

### 6.4 后续网关与纠正

C09 保留首个有效获批 → 开始另一申请 → 当前在办状态独立显示。纠正误判通过 O-G05，更新申请记录并重新判断客户是否仍有有效获批；原邮件保存，不改写证据。

### 6.5 删除

C02 危险操作 → O-C15 权限/影响/在办确认 → O-C16 执行与核验。删除成功后返回 C01；相关深链接进入对象不存在状态。邮箱保留，收到新邮件也不能重新创建被删客户。

客户专属申请、案件/待办和关联记录随档案删除，不在 M07 留隐藏副本。原邮件仍可在 M03 阅读，但“查看客户/申请”的旧入口失效；预审、补审及迟到任务都不能恢复旧客户或旧申请。后续需人工核对的邮件最多表现为未关联邮件，不自动复活已删除业务记录。

## 7. 权限与共享：页面上要说明的限制

| 场景 | 这版原型采用的规则 | 确认程度 |

## 9. 确认后逐张出图的顺序

每次只推进一个页面或一个关键状态；沿用已选视觉方向，不默认每页再出三个候选。复杂页面先确认正常态，再画它的子页/弹窗/异常态。

1. **C02 客户档案详情首页**：已选客户，资料与关联可读；不塞满所有字段。
2. C03 个人资料及编辑/驾照查看 → C04 企业 → C05 银行 → C06 材料及上传、预览、替换。
3. C07 网站与邮箱关联 → C08 材料审核 → C09 申请记录 → C10 操作记录。
4. C11 手工建档 → C12–C14 批量建档、人工确认、重复/失败状态。
5. G01/G02 申请列表与详情 → 明确要求、纠正、后续申请 → 客户删除确认和执行状态。
6. 现有 W02–W12 建站、批次、站点各页优化，重点保证与客户关联和原功能都保留。
7. M01–M08 邮件管理、阅读/翻译、撰写、预审/待确认、历史补审与申请联动。
8. R/T/S 资源、表格、设置和用户管理 → W01/A 全局与公共状态收尾。
