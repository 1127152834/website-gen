# 全局界面规范 v1

记录日期：2026-10-16。依据本轮用户对个人资料页和编辑抽屉的明确反馈。仅约束原型与后续界面设计，不代表代码实现或运行验收。

## 日期：统一美国格式

- 所有系统界面的完整日期展示和填写均采用 **MM/DD/YYYY**，补齐两位月、两位日、四位年。
- 范围包括列表、详情、状态区、页头、编辑字段、日历选中结果和操作记录；日期时间中的日期部分同样遵守此规范。
- 示例：生日 `04/18/1990`、驾照签发 `08/15/2022`、驾照到期 `08/15/2030`、获批 `10/12/2026`。
- 日期输入提示为 `MM/DD/YYYY`，支持手动输入和日历选择。不可依赖浏览器或电脑地区设置改为年/月/日或日/月/年，不默默交换月与日。
- 生日、驾照有效期属于日历日期，不因时区转换而前后移动一天。未提供的可选日期保持空值，不自动补今天。
- 本规范约束用户界面；档案文件名、设计版本记录和未来存储/接口格式不因此被要求迁移。

## 固定选项优先下拉

- 有明确固定选项的字段优先使用下拉选择，不将姓名、SSN、电话、邮箱、街道、城市、ZIP、信誉分等自由值生硬改成下拉。
- 两个地址的“州”分别选择，互不联动。选中值与选项都以州缩写为主，紧随较小的灰色英文全名，例如 **TX** Texas。
- 选项是完整州列表而非截图中四个示例；图中 TN Tennessee、TX Texas、UT Utah、VT Vermont 只是当前滚动位置。州缩写与全名来自同一字典，不能自由拼接。
- 长列表内部滚动；靠近窗口底部时向上展开，不被抽屉内容区裁切，也不遮住固定保存区。图中仅展开一个选择器，另一个保留收起态。

## 驾照附件：只显示上传状态

- 个人资料查看页的驾照正面、反面仅显示“已上传”或“未上传（可选）”，不展示缩略图、文件图块或文件名。
- 只有已上传项显示“查看”；工作人员点击后才进入图片预览。未上传项没有可用的图片查看入口。
- “已上传”只说明存在文件，不代表识别成功、人工确认或审核通过。识别确认来源可在对应字段来源中独立标注。
- 编辑个人资料抽屉只编辑字段，仍不负责证件文件上传/替换；两地址独立保存，不因不同而自动判错，不自动修改线上网站。

## 操作归因与申请定稿（10/17/2026 补充）

- **用户最新术语要求：界面列名统一使用“操作人”。**不再使用“最后修改人/最后操作人”作为归因列名；其业务含义仍是该字段/文件最后一次成功操作的人，不改成历史参与人列表。“申请负责人”是另一种角色，不能也改成操作人。动作详情可以解释录入、修改、上传、替换、识别发起或人工确认。
- 已在 C03 v3、C04 v2 与 C05 v2 落图并获用户确认；其他未修订图的历史原件不批量覆盖。银行原三栏布局使用每个字段自己的“操作人：姓名”，不强改为纵向表格。点击姓名查看时间/来源的提示放在资料内容标题行、编辑按钮左侧；详情层待后续单独设计。

- 当前字段/附件旁应能直接找到最后操作人的姓名；时间及来源可在行内次级信息或明确的展开入口查看，不能只藏在悬停提示中。文字不要小到难读；灰色辅助文字不等于可以低对比。
- 字段级归因不能用整页“最后编辑人”代替。编辑抽屉可集中显示只读“当前操作人”及保存说明，字段原归因保持可查；没有修改的字段不换人。不可让员工手选或代填操作人。
- O-C04 编辑抽屉统一使用只读“操作人：李敏 · 系统记录”和“查看字段操作人”。个人抽屉放在头部右侧空位，企业抽屉放在标题右侧空位，银行抽屉放在两条原说明下方空白区；新增信息不得下推原表单。该“操作人”表示当前登录账号在本次成功变更中的事实来源，不把主页面每个字段原有操作人批量替换成李敏。
- 编辑保存只有在字段值实际变化且保存成功时才更新该字段操作人；未改字段、取消、失败、校验未通过和既有申请定稿均保持不变。个人、企业仍保留“不自动修改网站”的原边界；银行仍不验证账户、不申请开户。“查看字段操作人”的具体详情态尚未绘制，不能把链接文字视为交互已验证。
- 企业办理状态与可选说明分别归因。状态未变只改说明时不得刷新状态操作人；没有既有说明操作人证据时只提供“查看说明操作人”入口，不虚构姓名。当前登录操作人只读，仍须以对应项实际变化并保存成功为更新条件。
- 上传队列中的“等待上传”不是成功文件，不提前写操作人或增加当前资料数量；多文件按每份实际成功结果分别归因，失败、取消、跳过项不更新。上传仍只保存客户当前资料，不自动提交网关，也不改既有申请定稿。
- 当前文件预览可显示文件操作人、操作动作和日期；当前文件原操作人与本次登录操作人必须分开。替换/移除只作用于当前档案且成功后才更新归因，失败保留原文件及归因；既有申请定稿不变。
- 当前档案与申请定稿要有文字标签，不仅靠颜色区分。定稿显示申请平台/标识、定稿时间和当时归因，不能被后续当前资料保存改写；附件须独立保全当时内容。
- 当前附件预览可按权限显示替换/移除；申请定稿预览只有查看、下载，无替换/移除/恢复版本按钮。移除整个客户档案的影响另列，不与单文件移除混为一谈。
- 替换提示建议：“当前资料将使用新文件，不保留中间版本；已保存的申请定稿不受影响。”移除提示建议：“仅从当前资料移除此文件，不提供旧版本恢复；已保存的申请定稿不受影响。”
- 负责人仅标在具体申请上，名称用“申请负责人”；准备阶段不出现固定客户负责人或必填分配控件。资料操作人与申请负责人使用不同标签。
- 申请定稿是内部记录，不代表向支付平台自动提交，也不代表平台确认收件。具体出图修改见[静态原型审查](F:/projects/website-gen/docs/design/customer-attribution-ui-audit-2026-10-17.md)。
