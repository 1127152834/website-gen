# 第 03 组：网站制作与管理 · 设计讨论稿 v1

日期：10/17/2026。状态：**讨论稿，尚未确认，尚未出图。**

本轮按用户要求先解释模块职责、功能和页面，再讨论，确认后才逐张画静态原型。Stitch 认证排查不再继续；不生成页面代码、不修改应用、不部署、不操作真实域名或邮箱。

## 1. 这个模块到底做什么

一句话：**把已经准备好的客户建站资料交给现有建站工具，制作并管理网站，直到员工能够检查、修改和确认上线。**

它回答四个实际问题：

1. 为哪个客户、哪家企业，用哪个域名和商业邮箱建站？
2. 这个站卖什么、品牌叫什么、使用哪些既有商品和价格配置？
3. 网站现在生成到哪一步，哪里失败，能执行什么明确操作？
4. 生成后怎样查看、修改、检查网站及配置网站交易邮件？

**不回答**“客户业务完成了多少”“员工下一步必须补什么材料”，不预测平台是否会批准申请。网站生成完成、已上线、客户网关获批，是三个不同事实。

## 2. 与客户模块怎么分工

| 区域 | 负责 | 不负责 |
| --- | --- | --- |
| 客户档案 C07「网站与邮箱」 | 记录客户和既有网站/商业邮箱的关联；查看摘要；进入建站或站点详情 | 不复制一套网站运行日志、AI 对话或上线功能 |
| 本组「网站制作与管理」 | 建站配置、任务执行、站点管理、网站修改、网站检查、交易发信配置 | 不保存第二套可编辑的客户个人/企业档案，不申请网关 |
| 邮件模块 | 商业邮箱收信、回信、阅读翻译、邮件 AI 与申请进度协作 | 不替代网站 WooCommerce 的交易发信配置 |
| 账号与域名模块 | Hostinger 账号、域名资源及其真实关联和状态 | 不以“已选域名”冒充购买或配置完成 |

C07、O-C11–O-C14 已有当前客户模块原型，本组直接承接，不重复绘制或擅自换版。当前 54 张图是参考与设计记录，不代表客户关联已经在应用中实现。

## 3. 保留什么，新增什么

### 3.1 沿用现有能力，不为“完整”重做一套

- 三步建站向导：经营主体、站点配置、确认启动。
- 已有独立建站、站点 CSV 导入、批次列表与详情。
- 站点列表、执行步骤与日志、重试和上线操作。
- 站点 AI 对话、变更记录、整体恢复/定时恢复。
- 网站复核报告、证据、修复和重新检查。
- 网站邮箱与交易发信配置、交易测试邮件。
- 建站总览的实际站点、批次、失败/检查结果和资源提醒。

这里“已有”仅指本地源码可见能力，不表示本轮验证过线上、供应商或真实建站结果。

现有向导允许公司或个人经营者，并不检查 EIN；客户模式的企业/EIN 前提属于新增联动，不能声称原系统已经支持。现有站点变更来源显示 `pi/你/定时恢复` 等标记，也不等于已经记录了员工姓名级操作人，人员归因需要单列设计。

### 3.2 本次新增或优化的设计

- 从客户档案进入向导，明确“本次为哪个客户建站”，带入相关公开资料。
- 在站点、批次中看到关联客户并返回档案；一个客户只关联一个网站。
- 不混淆当前客户档案值、本次提交的建站值、实际读取到的网站值。
- 统一界面风格、日期、状态和操作反馈，能定位真实操作人。
- 网站交易发信页提供跳转商业邮箱收件箱的入口，而不是内嵌第二套邮箱管理。

### 3.3 两个必须先说清楚的现有边界

**现有批量建站是“一个经营主体 + 多个网站”，不是“多个客户各自一个企业和网站”。**

不能直接在旧表格加一个客户列，就声称支持多客户同时建站。若需要多客户批量，每一项都必须独立带上客户、企业、域名和邮箱，防止把 A 客户的公司资料用到 B 客户的网站。本轮暂不把这种新批量方式列为已确认功能；已有独立批次能力不删除。

**现有“放弃网站/域名”与“删除客户档案”不是同一个操作。**

现有放弃动作涉及删除域名邮箱/别名及关闭域名续费；客户删除规则则是删除实际网站、域名保留并解绑、邮箱不处理。不得复用同一按钮或确认文案。未确认适用范围前，不把旧放弃动作放成关联客户站点的常规删除按钮；旧资源处理能力留在原有上下文，不凭此扩大删除权限。

## 4. 建议的业务路径

### 路径 A：从客户档案新建网站

1. 员工在 C07 点击新建网站。
2. 检查该客户没有已关联的网站，企业资料、企业办理结果/文件和 EIN 已齐备。缺什么就指向具体资料位置，不从“企业已办结”状态推断材料齐全。企业就绪所需具体字段/文件清单在详细设计时列明，不擅自增加银行流水或网关获批前置。
3. W02 复核建站主体及公开信息；W03 选择域名、商业邮箱和站点参数。
4. W04 确认本次实际提交的内容、客户关联和操作人，明确会调用 Hostinger、CJ 和模型并可能产生成本，再启动任务。
5. 进入 W06/W08 查看真实执行结果。保存任务成功不等于网站已经生成；生成成功不等于已上线。
6. 查看预览、网站复核或需要的修改，按实际可执行状态进行上线确认。
7. C07 与站点详情指向同一个站点，不另造网站副本；建站失败不删除客户档案。

### 路径 B：关联已经存在的网站

沿用 C07 → O-C11 的既有设计。关联不是生成、复制、重建或修改网站公开内容；关联之后进入同一个 W08。不得因关联成功自动把公司、邮箱或公开信息标为已一致。

### 路径 C：原有独立建站与批次

保留既有独立入口和站点 CSV 能力；CSV 不是客户资料导入。未关联客户的历史网站可以后续按现有客户关联设计处理。独立建站不得冒充已经满足客户发起流程的企业/EIN前置，后续关联也不会自动修正内容。

**讨论建议：**先把“单客户新建一站”和“关联已有站”设计清楚；多客户统一发起若确有高频需求，再单列设计，不悄悄改变原有一主体多站的含义。

## 5. 建站资料从哪里来

| 网站所需信息 | 来源 | 规则 |
| --- | --- | --- |
| 企业法定名称 | 客户企业档案 | 与店铺品牌分开，不用个人姓名代替 |
| 企业地址 | 客户企业档案 | 不使用驾照地址或当前住址冒充企业地址 |
| 公开联系电话 | 客户个人电话 | 按用户已确认规则带入；不另造客服电话 |
| 商业邮箱 | 客户关联商业邮箱，且需核对域名和可用性 | 不用个人邮箱；关联记录不等于已经连通或验证成功 |
| 商品品类 | 客户企业资料中的业务意愿 | 带入后展示本次选择；是否允许改成本次站点专用值，另行确认，不静默回写档案 |
| 店铺品牌名 | 本次站点配置/已有品牌 | 可与法定企业名称不同 |
| 域名 | 现有可用资源与客户关联 | 已占用、读取失败、不可用必须明确显示 |
| 商品数量、价格等参数 | 现有建站配置 | 沿用真实支持项，不凭空增加自动经营策略 |
| 订单处理、运输时效 | 现有经营信息配置 | 保留已有最短/最长时效，不从客户地址或商品品类臆测承诺 |
| EIN 与企业文件 | 企业就绪检查 | 不因用于建站前提就自动公开到网站 |

SSN、驾照照片、银行账号和流水不进入公开信息配置，不为建站无差别传递整份客户档案。

在客户模式，建议公开信息为“来源值 + 返回档案修正入口”，不要在向导偷偷形成第二套客户资料。客户资料后来修改，不自动修改已生成的网站；若需要同步，应由人明确确认具体改动，不覆盖旧申请定稿。

**域名与邮箱：**当前向导从既有域名和 Hostinger 有效邮箱中选择，并非自动采购域名或开通邮箱。读取失败不等于没有邮箱；一个候选可按已有规则选中，多个候选明确选择。客户已关联邮箱与域名不匹配时，不自动换成另一个地址。资源未就绪时提示去对应资源位置处理，不显示虚构“创建成功”。

沿用原清单 W01–W12，不重新编号。W02–W04 是一个向导的三步；W08–W12 是一个站点详情的五个子视图。

| ID | 页面/子视图 | 主要职责与操作 | 设计边界 |
| --- | --- | --- | --- |
| W01 | 建站总览 | 汇总站点、批次及真实异常；进入对应任务或站点 | 不增加业务完成率、猜测下一步或虚构 KPI |
| W02 | 新建网站 · 经营信息 | 确认客户、企业公开信息及来源，展示就绪问题 | 客户入口是新增关联设计；不恢复主体模板管理 |
| W03 | 新建网站 · 站点配置 | 域名、商业邮箱、品牌、品类、商品与价格等已有配置 | 客户模式一客户一站；独立模式保留已有能力，不混为多客户批量 |
| W04 | 新建网站 · 确认启动 | 复核本次输入、资源、关联与操作人，确认后启动 | 提交失败/未知分别处理，未知先核验，不盲目再建一站 |
| W05 | 批次列表 | 找到已提交的执行批次，查看任务状态和站点数量 | 批次是任务组织，不是客户资料批量导入 |
| W06 | 批次详情 | 按站点看步骤、结果、错误、日志；进入站点或执行真实支持的重试 | 部分成功不显示全部成功，不推断客户业务完成 |
| W07 | 站点列表 | 搜索域名/品牌/关联客户，按实际站点状态筛选，进入详情 | 关联客户显示为新增设计；不新增客户负责人 |
| W08 | 站点详情 · 概况 | 网站地址、关联客户、运行/上线状态、步骤、日志、适用动作 | 当前站点状态与客户/网关状态分开 |
| W09 | 站点详情 · AI 对话 | 描述网站修改要求、查看回复与执行反馈、停止、新对话 | 清空对话不是撤销修改；生成文字不是已应用成功 |
| W10 | 站点详情 · 邮箱与交易发信 | 检查邮箱/DNS/SMTP及交易发信配置，修复、验证、测试邮件 | 不是客服收件箱；不把 SMTP 接受写成收件人已收到，不测试付款 |
| W11 | 站点详情 · 变更记录 | 查看真实变更、操作来源、结果、定时恢复和整体恢复 | 是网站变更记录，不是恢复客户资料的中间版本库；无真实差异不捏造 diff |
| W12 | 站点详情 · 网站复核 | 查看检查结果和证据，单项/整体修复、重新检查、人工处理 | 不是材料审核，不保证网关获批；不可修复项仍保留 |

**导航建议：**沿用网站总览、新建网站、批次、站点等已有入口，不新增 12 项侧栏菜单。日常使用时客户档案可直接进入关联站点；操作完成后能回到原客户。

## 8. 状态与操作人怎么展示

- **执行状态、检查结果、上线状态独立表达。**“复核发现问题”不等于“生成失败”；“生成完成”不等于“已上线”。具体词需映射真实服务状态，不发明后端不存在的阶段。
- 允许展示有真实任务事件支持的步骤进度，不显示估算的客户业务完成率或无法计算的剩余时间。
- 列表无数据、筛选无结果、正在读取、读取失败分开；局部失败不清掉已读取内容。
- 创建/重试/上线的请求结果未知时先核验，不通过再次创建掩盖未知结果。
- 保存失败保留输入；客户数据在提交期间被其他员工改动时，展示差异供复核，不静默覆盖。
- 显示发起建站、修改网站、上线、修复、恢复等操作的操作人和实际结果；人发起 AI 执行时区分“发起人”和“AI 执行”，不能把 AI 写成申请负责人。
- 现有站点 AI 对话会直接应用网站修改，不是仅生成建议稿。入口和发送处应说明这一事实；执行失败不显示修改成功，新对话不撤销已应用结果，也不凭空增加尚未实现的逐次审批流程。
- 当前配置值只有成功变更才更新归因；失败、取消和未改值不覆盖原归因。网站已有变更记录继续保留，不将“客户材料无中间版本”误套成删除网站恢复记录。
- 准备资料、建站阶段不设固定客户负责人。申请负责人仍只属于具体网关申请，网站页面不新增分配客户负责人入口。

## 9. 需要讨论的三个决定

### Q1：日常是单客户逐个建站，还是多个客户集中启动？

建议先做好**单客户一次一站**，保留现有独立批次工具。如果每天常常把多个不同客户一起启动，再增加“按客户逐项确认”的批量方式；不能沿用共享同一家企业资料的旧批次表单。

### Q2：域名和商业邮箱由员工在进入向导前准备好吗？

已有业务说明包含先在 Hostinger 建域名/邮箱再生成网站，本稿先按**已准备好，系统选择并验证**设计。仍需明确：资源未就绪时回哪个现有入口、是否要在向导内提供资源办理入口；没有被确认和实现的采购/开通动作不画成一键成功。

### Q3：建好网站之后，员工何时确认上线？

现有生成结果保持维护模式，由员工人工上线；上线前读取最新 QA，有未解决项可以确认“仍然上线”，读取 QA 失败则不执行上线。本稿保留这些既有行为，分别展示生成和检查事实。需要讨论的是日常先检查、修改、上线的工作顺序和人员权限，而不是重新要求用户回答已有 QA 是否可跳过；不新增“必须全绿才准上线”的门槛，也不将材料 AI 审核的规则套到网站检查上。

## 10. 确认之后怎么画

1. 先定上述流程和批量组织，再画 W02 新建网站第一步，确定客户来源与资料展示。
2. 同风格接着画 W03/W04，贯通配置、确认启动及真实失败/未知反馈。
3. 画 W06 和 W08，接上任务执行结果与站点概况。
4. 补 W07/W05 列表，再画 W09–W12 和相应覆盖层。
