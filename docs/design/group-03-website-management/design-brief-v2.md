# 网站制作与管理 · UI 优化讨论稿 v2

日期：10/17/2026。**业务关系已按本轮反馈修正；页面布局仍是讨论方案，尚未出图或写代码。**

## 1. 目标已经明确，不再重新讨论核心业务

**一个客户 → 一家企业 → 一个网站。一次选一个客户或多个客户，使用同一套建站流程。**

当前核心建站能力沿用。我们优化的是：入口更顺手、批量配置不串客户、执行状态更清楚、常用操作更好找、视觉与客户模块一致。不把这次设计变成新的建站系统，也不拿旧数据结构反过来限制用户业务。

本稿取代 v1 的“多客户以后再做”“保留一主体多站特例”和单/多客户二选一问题。详见[范围调整 04](F:/projects/website-gen/docs/design/scope-amendment-04-one-company-one-site.md)。原稿保留作历史记录，不覆盖已完成的客户图片。

## 2. 什么保留，什么优化

| 保留现有功能 | 本次 UI 优化 |
| --- | --- |
| 建站参数、商品获取、AI 内容和现有流水线 | 客户、企业、域名、邮箱始终在同一条建站项中，减少来回查看 |
| 单次/批量任务与执行步骤 | 同一界面支持一条或多条客户建站项，不另做两套向导 |
| 站点与批次列表、失败重试、人工上线 | 搜索、状态和操作层级清晰；每个异常有对应目标和依据 |
| 网站 AI 对话、停止和新对话 | 对话区聚焦修改；实际执行结果可见，不把回复当作修改成功 |
| 网站复核、修复、证据、变更记录与恢复 | 集中在站点详情，主操作显眼，日志/证据/危险操作放二级位置 |
| 网站邮箱/DNS/SMTP和交易测试邮件 | 明确是网站发信配置，客服往来的收件箱仍在邮件模块 |

客户关联和“操作人”的显示需要在设计中明确，但不因此声称底层已实现。当前代码和未来实现衔接留到获准开发时；本轮不修改 API、数据库或流水线。

## 3. 入口和流程：单个、多个用一套

### 两种入口，同一规则

- **从客户档案进入：**带入当前客户，形成一条建站项；如果已有网站则打开已有站点，不再创建第二个。
- **从全局「新建网站」进入：**选择一个或多个客户，每位客户一条建站项。全局入口不是一企多站的例外，也不新增无驾照客户快建入口。
- **关联已有网站：**沿用客户模块 C07/O-C11 的当前设计；关联不是重新生成，不重画这套关联操作。

### 保持三步，但以客户建站项组织信息

**第一步 W02：客户与经营资料**

- 展示本次客户清单，行内显示客户、企业、资料就绪情况。
- 从客户档案带入企业名称、企业地址、客户个人电话和商业邮箱，来源明确，避免反复录入。
- 企业资料/EIN未就绪或已有网站时展示具体原因和可用入口，不用模糊的“资料不完整”。不要新增银行材料、网关获批前置。
- 一个客户只出现一次；多个客户各自保留自己的企业资料。既有订单处理和运输时效不丢失，属于各自建站项，不设整批共享企业表单。

**第二步 W03：逐客户配置网站**

- 每行始终能看到客户、企业、域名、商业邮箱、品牌名和品类，避免切换配置时认错对象。
- 商品数量、价格范围等既有参数收在对应项的展开区；单条时直接展示，不为了统一形式多加点击。
- 增减的是客户建站项，不是“给同一家企业再加一个网站”。
- 不默认跨客户复制企业、地址、电话或邮箱；域名重复、关联占用等问题定位到具体行。
- 域名和商业邮箱继续使用现有资源流程；读取失败不冒充没有资源，不额外画未经支持的一键采购/开通。

**第三步 W04：确认启动**

- 按客户逐项核对最终企业、网站配置和所用资源，不只显示整批公共信息。
- 明确本次操作人及既有外部调用/成本提示，确认后才提交。
- 有未就绪项时显示具体问题，可返回修正或明确移出本次清单；不静默跳过客户，也不伪造全部已提交。
- 提交结果未知时先核验已有记录，不通过重复点击再生成一个网站。
- 进入任务/站点查看真实结果；多项任务中失败、进行中和完成分别展示。

以上是 UI 组织方案，不预先承诺后端批次事务、并发或部分提交的实现方式。

## 4. 主要页面怎么优化

沿用 W01–W12 与既有覆盖层编号；不扩成 12 个侧栏菜单。

| ID | 页面/子页 | 主要 UI 优化 |
| --- | --- | --- |
| W01 | 建站总览 | 精简成实际任务、站点和异常入口；不做装饰性统计卡、业务完成率或自动下一步 |
| W02 | 新建网站 · 客户与经营资料 | 单选/多选客户共用界面；每项自己的企业资料和就绪提示，不再共享一个主体 |
| W03 | 新建网站 · 站点配置 | 每客户一条配置，常用字段在行内、详细参数按项展开，选一个客户也不绕复杂批量操作 |
| W04 | 新建网站 · 确认启动 | 展示每位客户最终将创建什么、使用什么资源，具体错误贴近对应项 |
| W05 | 批次列表 | 批次代表一次发起的建站任务集合；一客户也可是一项任务，不显示“同一企业多站”结构 |
| W06 | 批次详情 | 一行一个客户及其网站；各自的步骤、结果、错误和可执行动作明确，日志按需打开 |
| W07 | 网站列表 | 以客户/企业/品牌/域名及真实运行、上线状态为核心；搜索筛选集中，主要操作位置稳定 |
| W08 | 网站详情 · 概况 | 顶部固定识别客户、企业、域名；网站状态和适用操作靠近，执行步骤与日志分层 |
| W09 | 网站详情 · AI 对话 | 给对话足够空间，清楚显示修改正在执行/成功/失败；停止、新对话含义清楚 |
| W10 | 网站详情 · 邮箱与交易发信 | 按邮箱、DNS、SMTP/发信组织状态；修复和测试入口明确，危险密码操作不混入普通查看 |
| W11 | 网站详情 · 变更记录 | 记录可扫读，按需打开详情，恢复范围和冲突提示清楚，不伪造逐字段差异 |
| W12 | 网站详情 · 网站复核 | 问题列表、证据、修复及复查结果连贯；不能自动解决的项保留人工处理说明 |

**网站列表建议的主要信息：**客户、企业/品牌、域名、建站状态、上线状态、更新时间、操作。商业邮箱和完整步骤优先放在明确的展开/详情入口，不把整个档案塞进一行。

**网站详情建议的结构：**固定对象头部 + 概况 / AI 对话 / 邮箱与交易发信 / 变更记录 / 网站复核。打开网站、重试、上线仅在对应状态下可用；不能为了“操作齐全”每个状态都摆同一组按钮。

## 5. 弹窗和抽屉仍围绕现有动作

| ID | 界面 | 保留边界 |
| --- | --- | --- |
| O-W01 | 既有 CSV 站点配置导入结果 | 兼容入口的客户逐项映射另行细化，不放进首张正常流程图；不是客户资料导入，不能恢复一企多站或整批共享主体 |
| O-W02 | 移出本次建站项确认 | 移出未提交配置，不删除客户、企业或实际网站 |
| O-W03 | 启动前条件提示 | 按客户定位真实缺失/冲突，不混同材料 AI 审核 |
| O-W04 | 重试确认与反馈 | 明确目标和失败步骤，不盲目重复创建或采购 |
| O-W05 | 上线前网站复核提示 | 沿用现有 QA 行为，读取失败不是没有问题 |
| O-W06 | 步骤与日志详情 | 真实执行记录，清楚标明属于哪个客户的网站 |
| O-W07 | 新对话确认 | 只清空对话上下文，不撤销已应用的网站变更 |
| O-W08 | 变更详情 | 实际摘要、目标、操作人/来源、结果与可用恢复信息 |
| O-W09 | 整体恢复确认 | 显示范围和冲突，不用恢复网站去改客户资料 |
| O-W10 | 取消定时恢复确认 | 取消未来任务，不等于立即恢复 |
| O-W11 | 修复/复核运行面板 | 逐项结果，不用整批成功掩盖失败或需人工处理 |
| O-W12 | 证据图查看 | 来源与时间明确，不把旧证据当作实时状态 |
| O-W13 | 邮箱修复/SMTP 启用确认 | 目标、配置和密码影响明确，不静默更换商业邮箱 |
| O-W14 | 交易测试邮件 | 收件地址和发送结果明确，不是支付测试或自动联系客户 |

通用未保存、保存失败、并发修改等复用现有设计规则。CSV 适配不等于授权删除原能力；也不因为它存在就让正常建站流程违背已确认关系。

## 6. 不重新设计、不擅自改变的规则

- 企业资料/EIN先就绪；公开公司名称和地址取企业档案、电话取客户个人电话、邮箱用商业邮箱、品牌可以不同于法定名称。
- 当前档案、本次建站输入和实际网站内容分开；客户资料修改不自动改线上网站，也不改既有网关申请定稿。
- 建站生成完成、上线、网关获批完成分开。保留现有维护模式及人工上线：有未解决 QA 可按既有提示确认继续，QA 读取失败不执行上线。
- 网站 AI 对话是实际修改，不只是建议；新对话不撤销修改。网站复核不是材料审核，也不保证支付平台获批。
- 字段和附件的当前归因用“操作人”；申请负责人仅属于具体网关申请。建站不引入固定客户负责人。
- 原有网站变更/恢复记录保留，不把材料无中间版本规则套用成删除网站变更记录。
- “放弃域名/网站”与“删除客户档案”影响不同，不共用按钮和确认语义；不新增危险操作权限。
- 不恢复主体模板、独立材料页、无驾照手工建档、客户资料/Grist导入或支付测试。

## 7. 视觉和下一步讨论

白底、墨蓝标题与正文、灰蓝辅助文字、深藏蓝主按钮、亮蓝仅用于真实交互；保持客户模块的圆角、边框、表格和抽屉风格。日期 MM/DD/YYYY，固定选项优先下拉，州缩写配灰色英文全名。按钮和状态不能只靠颜色区分。

不换一套新主题、不为了“高级感”加大卡片/环形进度，不把已有页面拆出大量新路由。改善布局、表单密度、错误定位和操作入口，但保留原有功能。

**建议首张原型从 W03「新建网站 · 站点配置」开始：**同一张图展示多个客户各自一行，当前选中项展开详细参数，最能验证单个/多个共用流程及一企一站关系。单客户视图复用同一结构，不再做另一套业务流程。第一步 W02、确认 W04 和结果页随后按同一风格补齐。

下一轮只需要讨论上述页面组织是否顺手，不再让用户在单客户或多客户之间选一个。确认布局方向后再出图；本次没有生成图片、修改应用或访问真实业务服务。
