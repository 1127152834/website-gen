# 其他模块 55 条提示的业务能力与权限风险审阅

日期：10/17/2026（PT）  
范围：`prompts/other-modules-scenes.json`。  
方法：只核对提示中可能被理解为“系统已经具备”的功能、权限与保护机制；不重复词数、尺寸、JSON 字段等格式检查，也不修改提示或主计划。

## 结论

- **1 个硬冲突：** A09 触及源码明确禁止向通用助手暴露的申请来源邮件能力。
- **1 组角色模型冲突：** S08/O-S06/O-S07/O-S08 使用“运营”作为系统角色，但当前认证模型只有 `admin/user`。
- **6 个设计已授权、源码尚未实现的能力缺口：** 可以继续作为一期静态目标，但图稿、图册和最终汇报必须标成拟新增/未验证，不能称为现有保护或已完成能力。
- 其余提示未发现需要升级为真实业务风险的能力或权限假设。

## 具体风险（最多 8 项）

### 1. A09 — 通用助手打开 APP-002 来源邮件

**等级：阻断性提示风险。**

提示要求用户输入 `打开 APP-002 的来源邮件` 后得到本地导航结果。源码虽然允许通用助手查询普通邮箱和读取已知邮件，但 `src/backend/assistant-tools.ts` 明确排除：

- `mail.cases.list`
- `mail.cases.detail`
- `mail.cases.sourceMessage`
- `mail.triage.sourcePreview`

排除理由均是申请事项和来源正文不自动成为通用助手能力。助手没有受支持的工具把 `APP-002` 解析为专用案件来源邮件，因此该场景会暗示越过专用安全阅读器。

**审阅结论：** 后续出图前应把场景改为普通邮箱查询，或让助手明确说明“申请来源需在邮件事项页面打开”并只提供安全导航；不能画成助手已经读取或定位了 APP-002 的专用来源正文。

### 2. S08 / O-S06 / O-S07 / O-S08 — “运营”角色被画成真实权限角色

**等级：高。**

演示人物要求陈佳、王磊显示为运营，但当前 `src/shared/auth.ts` 只有 `admin | user`，`src/renderer/src/features/users/validation.ts` 也只接受这两个值，用户管理界面显示 `管理员 / 普通用户`。提示若在角色下拉、表格或确认框直接显示可配置的“运营”，会暗示第三种权限集合已经存在。

**审阅结论：** 静态图若保留业务称谓，应写成 `普通用户（运营）` 或明确“运营为展示称谓，权限仍是普通用户”；不得画出可提交的 `运营` 角色选项，除非后续另有已批准的权限模型设计和实现。

### 3. O-M05 — 客户/申请关联自动阻止永久删除邮箱

**等级：高，设计已授权但源码未实现。**

提示要求邮箱因 Alex Morgan / APP-002 关联而阻止删除。既定页面设计确实要求这项防误删保护，但当前 `mail-management-page.tsx` 和 `mail-page.tsx` 的删除流程只做确认后调用 `mail.delete`，未见客户/申请关系预检。

**审阅结论：** 该图可作为拟新增安全目标，但证据和图册必须标注“保护逻辑未实现/未验证”；不能用静态禁用按钮证明真实删除已被服务端阻止。

### 4. R04 — 客户关联自动阻止放弃站点/域名资源

**等级：高，设计已授权但源码未实现。**

提示及关键状态队列要求 `已关联客户，不能直接放弃`。这是既定设计边界，但当前放弃流程仍基于域名、站点和账号参数执行，客户业务关联尚未成为可验证的服务端阻断条件。

**审阅结论：** 可画成目标态，但必须保留“拟新增客户关联预检”；不能声称当前 `abandon.start` 已具备该保护，也不能把它与客户删除复用为同一动作。

### 5. S10 / O-S10 — 联系人规则直接关联客户和具体 APP-002

**等级：中高，设计已授权但数据结构未实现。**

提示要求规则包含客户/具体申请。当前 `ContactMapping` 和 `ContactMappingSchema` 支持 provider、site、mailbox、sender、domain、reason、operator/version，但没有 `customerId` 或 `applicationId`；现有 UI 保存时 `siteId` 仍传 `null`。

**审阅结论：** 规则页可以展示为拟新增字段，但不得描述为当前已保存的真实 APP-002 绑定。尤其不能因为发件地址/域名匹配就宣称来源或申请身份已经确认。

### 6. A08 — 全局搜索中的客户姓名/企业索引

**等级：中，设计已授权但源码未实现。**

当前 `components/search.tsx` 只索引导航页面、站点域名和设置分区；没有客户数据源。A08 的 Alex Morgan / Northline LLC 搜索结果属于已批准的新客户索引方向，不是现有能力。

**审阅结论：** 可作为一期目标图，但需标记拟新增索引；静态结果不能被写成当前搜索、权限过滤或租户隔离已经通过验证。

### 7. S03 — 驾照识别/材料审核被画成可分配模型用途

**等级：中。**

提示要求展示这两个用途占位。当前 `models.setRole` 只接受 `agent / vision / bulk / review / translation`；没有独立 `license_recognition` 或 `material_review` 角色。既定设计只说拟新增用途。

**审阅结论：** 必须保持 `规划中/不可选择` 或明确复用哪个现有角色；不能画成已保存、已就绪的两个新用途，否则会制造不存在的配置与权限语义。

### 8. O-A05 — 并发提示包含未定义的复制本地内容与按权限重试

**等级：中。**

既定设计支持“比较/重新读取、不静默覆盖”，但提示动作还包含 `复制本地内容` 和 `按权限重试`。当前没有统一并发冲突组件或这些动作的实现证据；“按权限重试”尤其可能让用户误以为客户端能提升或重新协商权限。

**审阅结论：** 独立状态图应以 `比较更改 / 重新读取 / 取消` 为主；复制只能描述为本地文本复制，不得保存回对象；不得出现暗示权限升级的重试动作。

## 未升级为风险的边界

- M05–M07 已明确为此前授权开启后的独立历史场景，与 S09 默认关闭不再构成实时状态冲突。
- 邮件翻译、已读、废纸篓、发送确认、历史补审及专用邮件 AI 授权在当前源码中均有对应边界，不因是静态图而重复列为风险。
- Grist 原生 iframe、第三方边界和未配置空态与既定设计及当前 renderer 一致。
- 所有“设计已授权但源码未实现”的条目仍只能证明目标界面，不证明权限、服务端校验、租户隔离或破坏性操作保护已经落地。
