# 客户档案与资料

> **设计说明：**本页介绍的是当前一期静态原型，帮助内部员工和管理员理解页面怎么配合使用。图片不可点击，也不代表功能已经上线；真实保存、识别、审核和删除结果仍需在后续系统中验证。

**一句话用途：**把一位客户从“上传驾照建档”到个人、企业、银行、附件、网站和邮箱资料整理到同一份内部档案中，供后续建站与支付网关申请共同使用。

## 在整个项目中的位置

客户档案是后续工作的资料底座。系统按“一位客户、一家企业、一个网站、一个商业邮箱”组织关系，建站和网关申请都从这里读取已经核对的资料。客户不会登录这套系统，也不需要自己在页面中操作。

企业注册本身在系统外办理；这里记录办理状态、结果和相关文件。**EIN 是企业的联邦税号，用来识别企业的税务身份。**企业资料和 EIN 齐全后，才能进入建站流程。

## 谁用、什么时候用

- **资料录入人员：**收到客户驾照和业务资料时建档，核对识别结果并补全信息。
- **内部经办人员：**建站、申请网关或回复资料问题前，回到档案核对当前内容。
- **管理员：**处理重复客户、保存冲突、失败记录或删除影响确认。

准备资料阶段没有固定“客户负责人”。每个字段和每份附件只显示当前最后一次成功操作的操作人；取消、失败或仅查看不会改变操作人，也不会形成一套完整的历史变更记录。

## 使用前准备

1. 准备每位客户的驾照正面图片。无论单张还是批量建档，每一位客户都必须上传。
2. 准备个人联系方式，并把“驾照上的地址”和“当前居住地址”分开核对，不能用一个地址覆盖另一个。
3. 按实际情况准备企业资料、EIN、银行资料以及对应附件。附件放在个人、企业或银行等相应区域，没有单独的“材料页”。
4. 如需关联业务资源，先确认要使用的网站和商业邮箱，避免把其他客户的资源接入本档案。

## 常用顺序

1. 在“上传驾照建档”中选择一张或多张正面图片。
2. 等待识别后逐项人工核对姓名、证件信息和驾照地址。识别失败时仍需保留并上传驾照正面，再依据图片人工录入；不能跳过驾照直接建档。
3. 处理疑似重复、同名或资料差异，确认后查看建档结果。
4. 分别完善个人资料与两个地址、企业资料与 EIN、银行资料和各区域附件。
5. 记录企业在系统外的办理状态与结果，并关联该客户现有的网站和商业邮箱。
6. 需要申请前检查时查看资料审核结果。AI 检查只供参考；有问题、未检查或检查失败时，员工知情并人工确认后仍可继续。修改资料或更换申请平台时，只重审受影响的部分。
7. 需要追查当前资料来源时查看最后成功操作人；需要删除客户时，先阅读影响范围再确认。

## 两个具体故事

**故事一：批量建档里有一张模糊驾照。**李敏一次上传了五位客户的驾照正面，其中四张识别成功，一张无法提取字段。她先核对成功的四份，再打开模糊图片人工录入。因为原始驾照仍随该客户保存，所以这位客户可以继续建档；系统不会把“识别失败”误解成“可以不交驾照”。

**故事二：企业地址更新，但旧申请不跟着变。**王芳把客户当前企业地址改为新地址，并替换了对应企业文件。当前档案显示王芳为这些项目的最后操作人；此前网关申请保存的资料定稿仍保持原样，已发布网站内容也不会自动改写。团队可据此决定是否复核相关资料，而不是假定所有地方已经同步。

## 常见误解与失败处理

- **“资料审核通过就等于平台会批准。”**不是。检查只提供参考，最终是否获批由外部平台决定。
- **“可以先手工建客户，以后再补驾照。”**不可以。驾照正面是建档前提；识别失败只会转为对照原图人工录入。
- **“资料都在一个材料清单里。”**不是。文件跟随个人、企业、银行等对应区域保存，便于理解用途。
- **“操作人就是客户负责人，也能看到完整修改历史。”**不是。准备阶段没有固定负责人；这里只显示各字段或附件当前最后一次成功操作的人。
- **上传或保存结果不确定：**先回到列表或档案核实结果，不要立即重复提交。部分上传失败时只补失败项；保存失败时保留原输入，确认网络和当前记录后再试。
- **多人同时修改：**先查看最新内容，再决定保留哪一版，避免覆盖同事刚保存的资料。
- **删除客户：**确认画面会说明影响。删除客户时，关联网站会一并删除，并解除网站与域名的关系；商业邮箱不会删除。有正在办理的申请时必须再次确认，再决定是否继续。
