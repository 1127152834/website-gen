## 硬性业务约束

- 内部员工系统，客户不登录；先上传驾照正面才可建档，识别后人工核对；驾照地址与当前住址分开。
- 一客户一企业一网站；多个网关申请可历史留存，但同一客户同时仅一个进行中。首个有效获批决定客户完成；误判纠正须重新计算，不被后续申请误覆盖。
- 准备资料没有固定客户负责人。字段和附件显示当前最后成功操作的“操作人”；仅具体网关申请有“申请负责人”。
- 没有独立材料页、无驾照手工建档、客户表格导入、共享企业模板或支付测试页。材料审核保留且仅供参考；人工可在明确确认后继续申请。
- 企业资料与 EIN 齐备才能建站。网站公开企业名/地址来自企业档案，电话来自客户个人电话，邮箱为客户商业邮箱；品牌名可不同。
- 当前资料、网关申请时点定稿、网站已发布内容分开；修改当前资料不自动修改后两者。
- 邮件 AI 可推进申请并含获批，人工可纠正，新邮件仍可继续推进；必须标明关联对象、证据及不确定/冲突，不伪造判断出的下一步。
- 网站生成完成、网站上线、网关获批是不同事实。危险资源放弃与删除客户是不同影响范围。
- 日期 MM/DD/YYYY；固定选项优先下拉；州以缩写和灰色全名显示；驾照附件查看页只显示上传状态，点开才看图。

- 只使用虚构 DEMO 数据及 `.example` 域名，不读取真实驾照、SSN、密钥或邮件内容。
- 本地源码只读用于判断现有能力，不将本地功能入口当作服务实际可用/已上线的证据。
- [写入前基线](evidence/baseline.json)保留 324 个设计文件和 344 个应用源码文件哈希；新稿独立保存，原有文档若需更新先另行备份。
- 图片生成使用内置 ImageGen；提示词留在 prompts，图像复制进 screens，源图保留，逐张记录哈希和审阅。
- 进度以实际已保存、已审阅文件为准。未生成、修复中或未检查不能记为完成；不以文字规划代替用户要求的图。
- 滚动、键盘、响应式和真实交互只能写成设计约束，不能声称静态图片已经运行验证。
- 任务未完成时继续从最新已验证检查点推进，不把阶段交付当最终完成。
