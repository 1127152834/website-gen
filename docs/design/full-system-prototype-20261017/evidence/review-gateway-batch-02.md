## 2. G04-v1：内部开始事件不能引用未来邮件

### 必改 G04-1：第一行的事件、证据与动作不匹配

第一行时间10/16/2026 14:00 PT，却写“已提交申请并保存快照”，引用次日E-102的July–September原文，并带“查看原邮件”按钮。

风险：

- 让员工以为系统保存记录已等于向平台提交/被平台受理。
- 错误的证据入口将不相关邮件包装成开始依据。

最小修复第一行即可：
- 事件写“开始记录”或“申请与定稿已保存”；不要仅以“—→审核中”暗示保存本身证明平台正在审核。
- 来源“内部操作”；操作人李敏；时间继续10/16/2026 14:00 PT。
- 依据写“仅保存系统内申请记录和当时资料，不代表平台端提交成功。”
- 动作改为“查看申请定稿”，删除所有原邮件引用。
- 这是内部事件说明，不新增支付平台状态枚举。若保留人工记录的审核中状态，必须明确它是内部记录，不能声称平台已实时受理。

### 必改 G04-2：月份表述统一美国格式

第4行说明为“2026年7月、8月和9月”。改成“邮件明确要求提供07/2026–09/2026银行对账单”，保留同一英文原文。不要把月份变更成更晚月份或自动缺件建议。
