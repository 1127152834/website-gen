## 问题、图证据与修正

| 问题 | 图路径与可见证据 | 文案修正 |
|---|---|---|
| 新员工不易分清内部账号入口、权限角色和职责备注 | `08-内部用户与权限/01-用户管理-内部用户列表.png`：左侧“系统”下有“用户管理”；列表区分角色、职责备注、状态和必须改密 | 增加客户不登录、管理员/普通用户是角色、“运营”只是职责备注的说明，并增加任务导航表 |
| 重置密码容易被理解成只替换密码 | `08-内部用户与权限/03-用户管理-重置用户密码.png`：勾选让所有会话失效及下次登录强制改密 | 把两项后果放入操作步骤和误区，不把弹窗出现当成成功 |
| 停用账号容易被误写成删除记录或完成负责人交接 | `08-内部用户与权限/04-用户管理-启用或停用用户确认.png`：停用后不能登录，记录保留，负责人交接另行安排。主代理补充核对 `03-支付网关申请/05-开始申请-确认平台与申请负责人.png`、`03-支付网关申请/08-申请详情-本次申请概览.png`、`03-支付网关申请/16-申请状态-人工更新或纠正.png`：负责人只在开始时选择，后两页无改派入口 | 明确停用不等于交接；删除“到具体申请中改派”的承诺，写明当前原型未展示改派入口，应先由管理员协调 |
| 首次强制改密、本人主动改密和管理员重置容易混淆 | `09-登录与全局工具/01-系统登录-内部用户登录.png` 至 `03-账号安全-主动修改自己的密码.png`：入口和后果分别展示 | 按先登录、首次改密、主动改密、管理员重置的顺序说明 |
| 去用户管理和设置的路径不清楚 | `09-登录与全局工具/04-账号入口-个人菜单.png`、`05-通用导航-以驾照上传页为例.png`：个人菜单与左侧“系统”导航分开 | 增加新员工任务导航表，区分个人菜单、设置、用户管理 |
| 搜索结果和助手回答容易被当成完成证明 | `09-登录与全局工具/07-全局搜索-查找系统内容.png` 至 `09-全局助手-工具操作确认.png`：搜索按类别展示；助手限制本地内容；修改动作需要确认 | 明确搜索只负责导航，助手回答不等于执行，敏感信息不应输入，动作需确认并核对结果 |
| 新对话可能被误解为撤销操作 | `09-登录与全局工具/10-全局助手-开始新对话确认.png`：已执行操作不回滚，待确认操作取消 | 单列“开始新对话不会撤销操作” |
| 离开、并发修改和记录已删除需要不同处理 | `09-登录与全局工具/11-编辑保护-未保存就离开确认.png` 至 `13-编辑保护-保存时发现记录已被删除.png`：分别展示丢弃输入、三方值对比和禁止重建 | 分三种场景写恢复顺序，避免承诺自动合并、覆盖或重建 |
| 登录失效、身份复核失败、无权限、页面不存在和服务异常易被混为一类 | `09-登录与全局工具/14-登录异常-会话已失效.png` 至 `18-访问异常-服务暂时不可用.png`：五个独立页面和恢复动作 | 分别解释后果和恢复入口；请求标识不写成业务完成编号 |

## 边界与遗留验证

- PNG 是静态原型，不能验证真实登录、权限判断、密码更新、会话失效、保存冲突或服务恢复是否已实现。
- 当前原型未展示网关申请负责人改派入口；文档只说明管理员需要协调，不承诺可在某个未展示页面完成改派。
- 文档没有把搜索命中、助手回答、弹窗出现、请求标识或示例状态当成真实完成结果。
