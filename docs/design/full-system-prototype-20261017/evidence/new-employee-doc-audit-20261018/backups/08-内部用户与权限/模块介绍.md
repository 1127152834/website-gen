# 内部用户与权限

> **原型说明：**本目录展示的是静态界面图片，图片中的创建、重置、启用和停用按钮都不可点击，也不代表账号或权限功能已经上线。

**一句话用途：**让管理员创建和维护团队内部登录账号，控制员工能否进入系统，同时保留由这些员工完成的业务记录。

## 它在项目中的位置

整个应用只供团队内部使用，客户不会获得登录账号。这个模块管理的是员工身份，不是客户档案、客户商业邮箱或支付平台账号。原型中只有两种真实权限角色：**管理员**和**普通用户**；“运营”等文字只是职责备注，方便说明员工平时做什么，不是第三种角色，也不代表一套未展示的精细权限矩阵。

代表页面：[查看内部用户列表](01-用户管理-内部用户列表.png)

## 谁在什么时候使用

- 管理员在新员工需要使用系统时创建内部账号，并选择管理员或普通用户角色。
- 员工忘记内部登录密码、首次登录需要更换初始密码时，管理员可发起重置。
- 员工离岗或暂时不应访问系统时，管理员停用账号；需要恢复访问时再启用。

## 常用流程

1. **查找用户：**在内部用户列表按用户名、角色或状态筛选，先确认操作对象，避免改错账号。
2. **创建用户：**填写内部用户名、选择两种角色之一并设置初始密码。创建成功后，把初始登录信息通过团队认可的安全方式交给本人；用户下次登录时按提示修改密码。
3. **重置密码：**选中明确的内部用户，设置新的初始密码并确认。重置的是业务工作台登录密码，不是客户的商业邮箱密码，也不修改外部平台授权信息。
4. **启用或停用：**操作前阅读确认框中的当前状态和访问影响。停用会阻止该员工继续进入系统，但不会删除客户资料、历史操作记录或已经留存的业务证据；具体网关申请的负责人交接也要另行处理。
5. **核对结果：**若操作失败、权限不足或用户状态已被别人改变，应重新读取列表后再决定，不要根据旧页面重复提交。

## 一个虚构用户故事

管理员林悦为新同事赵宁创建普通用户账号，并在职责备注中写“运营”。这不表示赵宁拥有名为“运营”的第三种权限角色。赵宁首次登录后必须修改初始密码。数月后赵宁休假，林悦从列表中确认对象后停用账号；客户档案、赵宁过去的操作记录和某个网关申请都仍然保留。若申请需要换负责人，林悦再到具体申请中单独办理，而不是把停用账号当成交接完成。

## 常见误区与异常处理

- **误区：客户也在这里开账号。**这里仅管理内部员工；客户资料在客户模块中维护。
- **误区：“运营”是一种权限。**它只是职责备注，真实角色只有管理员和普通用户。
- **误区：重置用户密码会改变客户邮箱密码。**两者完全不同；客户商业邮箱由邮箱相关流程处理。
- **误区：停用等于删除。**停用只改变访问能力，不删除客户资料、业务记录或历史操作人信息。
- **异常：重复用户名、权限不足或目标已变化。**停止提交，重新确认当前账号和页面状态；不要覆盖别人刚完成的操作。
- **异常：账号已停用或已不存在。**先返回列表核对，不要用旧弹窗继续重置或启停。
