# 网站建设与站点管理

> 这里描述原型设计用法，图片不可操作，不代表功能上线。页面中的客户、企业、域名、进度和结果都是虚构示例，真实保存、建站、发信和上线仍需在后续系统中验证。

**一句话用途：**把已经具备企业资料和 EIN 的客户按三步发起建站，再从批次和站点两个角度查看进度、处理异常、维护网站并完成上线前复核。

## 在整个项目中的位置

这个模块位于客户档案之后、网站日常维护之前。系统按“一位客户、一家企业、一个网站、一个商业邮箱”组织业务：可以一次为一位或多位客户建站，但不是为同一家企业建立多个网站。客户不登录，所有选择、确认和处理都由内部员工或管理员完成。

建站使用客户档案中的企业资料。公开页面上的企业法定名称和地址来自企业档案；店铺品牌名可以不同。联系邮箱使用商业邮箱，联系电话使用客户个人电话。当前档案、本次站点配置和已经发布的网站内容彼此分开，修改其中一处不会自动改写其他两处。

## 谁用、什么时候用

- **建站经办人员：**选择已准备好的客户，填写经营信息和站点配置，确认后启动。
- **运营人员：**查看批次与单个站点的进度、等待原因、失败步骤和变更记录。
- **管理员或复核人员：**处理重试、恢复冲突、发信配置和上线前问题。

开始前应确认企业资料与 EIN 都已齐全，客户尚未建立网站，并准备好域名、商业邮箱及所需站点资源。系统不导入客户表格；CSV 入口只用于导入**站点配置**，不能用来新增客户或建立企业档案。

## 按工作顺序使用

1. 在建站总览进入“新建网站”，选择一位或多位符合条件的客户。已有网站的客户应先回到客户档案关联现有网站，不要重复新建。多客户时使用纵向工作表，搜索或翻页只改变当前显示，不改变已经选择的完整名单。
2. 完成三步向导：第一步核对客户与经营资料；第二步填写站点配置或导入站点配置 CSV；第三步查看完整清单并确认启动。移出某一项只影响本次建站名单，不会删除客户。
3. 提交后到批次列表和批次详情查看每位客户的独立进度。一个站点失败不会代表其他站点也失败；等待外部服务、建站中、失败和建成要分别判断。
4. 建成后从站点列表进入详情，查看概况、与 AI 对话修改网站、商业邮箱与网站发信、变更记录及网站复核。网站发信测试只是检查网站邮件发送，不是测试付款；本系统也不负责测试付款或代运营。
5. 上线前查看复核结果。可修复项与必须人工处理项分开；读取失败时先重新获取结果，不能把“读不到”当成“没有问题”。
6. 需要恢复历史版本时，先查看改动详情和影响。若目标版本之后又有变更，恢复可能被冲突阻止，不能承诺一键完整恢复。

## 两个具体故事

**故事一：三位客户一起建站。**李敏选择三位资料已齐的客户，在同一张工作表分别核对经营资料，再为每位客户配置自己的域名与商业邮箱。启动后，一位正在生成页面，一位等待外部服务，一位在某一步失败。她只对失败项查看记录并确认重试，没有把整批都重新提交。

**故事二：网站建成但还不能上线。**王芳看到某站点已经生成完成，但上线前复核仍有两个可修复问题和一个需要人工核对的商品图片。她先处理问题并重新复核，未把“建成”写成“已上线”，也未由网站状态推断支付网关已经获批。

## 常见误解与异常处理

- **“建站完成、网站上线、网关获批是一回事。”**不是。这是三个独立事实，要分别查看。
- **“CSV 可以导入客户资料。”**不可以。它只导入站点配置；客户与企业资料来自现有档案。
- **“筛选后只会提交当前几行。”**不一定。确认页应以完整已选名单为准，先定位隐藏页中的缺项或冲突。
- **资源读取失败或暂无资源：**保留已填内容，核对资源状态后重试，不要改用其他客户的域名、邮箱或企业资料。
- **提交结果不确定：**先查批次和站点是否已经生成记录，再决定是否重试，避免重复建站。
- **测试邮件结果未知：**先核查已发送记录和收件情况，不要连续重发；SMTP 接受也不等于最终送达。
- **恢复被阻止：**核对目标版本之后的变更，再决定如何处理；不要覆盖同事后来保存的修改。
