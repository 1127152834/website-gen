- 180 个中文图片副本对应 179 个不同的原图文件：通用导航和客户上传页共用同一原图，在两个目录各存一份。
- 另有 11 个复用入口直接链接对应页面，不生成重复功能。合计完整对应原覆盖清单的 191 个标识。
- 9 份模块介绍包含项目位置、适用人员、使用顺序、虚构用户故事、易错点与异常处理。
- 原型中未选用的候选版、历史版本和旧审阅证据继续保留在原档案，不混入当前阅读目录。
- 本次没有重画或修改图片内容，也没有编写应用功能、运行部署或调用真实业务服务。

## 检查结果

1. **图片一致性：通过。** 逐一计算原图、清单预期值和新副本的 SHA-256；180 组全部相符。不是靠缩略图相似来判断，也不声称本次重新审阅全部画面设计。
2. **覆盖与命名：通过。** 9 个模块齐全，图片使用中文页面／功能名称，180 项图片和 11 个复用入口均有对应关系，无遗漏、重复标识或失效目标。
3. **文档与链接：通过。** 每个模块都有介绍和目录；阅读版全部 Markdown 本地链接均能找到文件。具体检查数量记录在校验 JSON 中。
4. **文案复核：通过。** 根指南及各模块说明已复核。修正了“一个商业邮箱”遗漏、把邮箱误写成资源放弃独立入口、未经证明的权限表述，以及长期凭据和一次性授权值的说明差异；补充了常见术语的白话解释。
5. **旧档案保护：通过。** 原图、覆盖表和原分组图册未改；原档案 README 只增加一个新阅读版入口，修改前已备份。复核其余正文没有变化。
6. **应用源码回归：通过。** 原设计基线记录的 344 个应用源码文件哈希仍一致。本次工作仅涉及设计材料，不把这个结果等同于完整应用测试。

## 与真实系统的区别

这些说明讲的是已确定原型的预期用法。静态图片不能证明按钮可用、权限已执行、AI 判断准确、邮件已送达或第三方已连接。本轮不进行这类功能验收，也没有真实客户或平台操作。

业务关系和已确认的流程保持不变；图片整理不会新增任何功能。后续开发仍需单独实现和验证。

## 如何回退这次整理

这次采用“保留原档，增加阅读副本”的方式：

1. 需要回到旧阅读方式时，可直接打开[原设计档案](../full-system-prototype-20261017/README.md)。
2. 若要移除新入口，只需撤掉原 README 新增的“新用户阅读入口”一段；修改前文件保存在 `../full-system-prototype-20261017/evidence/backups/module-reader-final/original-README.before-module-link.md`。若此后已有其他编辑，应先比较，不要整份覆盖后来的内容。
3. 新目录可以保留为独立归档，不需要删除任何原图；本轮没有执行目录删除。
4. 文案润色前的副本保存在原设计档案的 `evidence/backups/module-reader-copy-review/` 与 `evidence/backups/module-reader-final/`，可按需对照恢复。

## 后续维护约定

本阅读版不是自动同步目录。原型更新后，应先确认新图是有效版本，再更新中文副本、页面对应关系和目录，并重新校验。不要把旧图片只改一个文件名就当成新设计，也不要把历史候选版误当成当前方案。
