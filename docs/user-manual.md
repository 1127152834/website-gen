# 独立站 AI 工厂 · 操作手册

> 适用版本：0.1.0（2026-10-15）。这是一个只在你自己电脑上运行的桌面工具：用你的 Hostinger 账号和已购域名，自动建出美国市场的 WooCommerce 独立站，从 CJdropshipping 取商品资料、由 AI 写文案和政策，验收后一键上线；上线后可以和内置的 AI 助手 pi 对话修改内容。

---

## 工作区界面（2026-10-16 更新）

Web 工作区沿用原有业务功能与书签地址，界面已改为 shadcn-admin 风格。下面描述新版界面；后续历史章节中的桌面安装、托盘及旧截图说明不代表本次界面改造的验证结果。

- **主导航**分为「建站与运营」（总览、建站、批次、站点）、「资源」（账号、邮箱、表格）和「系统」（设置、管理员可见的用户管理）。顶部按钮或 `Ctrl/⌘+B` 可以折叠导航；手机上以抽屉打开，选择页面、点击遮罩或按 Escape 关闭。
- 顶部显示后台连接状态、**搜索工作区**、浅色/深色/跟随系统主题与用户菜单。`Ctrl/⌘+K` 可搜索页面、站点域名和设置分区；用户菜单提供修改密码和退出登录。邮箱导航数字是当前工作区未读总数。
- **首次登录**仍需先修改初始密码。失效会话会返回登录页；非管理员不能进入用户管理。切回窗口时会复核身份，同一用户复核不重建工作区，切换身份会清空之前的缓存和待确认操作。
- **总览**汇总站点状态；**建站**是「经营主体 → 站点资料 → 确认提交」三步向导，保留主体模板与 CSV 导入；**批次**展示批次列表、站点进度、步骤及日志。
- **站点**保留「概况 / 对话 / 邮箱 / 变更记录 / 复核报告」五个页签。复核报告仍按待处理、需要你补充、已修复分组，支持单项修复、一键修复全部、重新复核及实时修复记录。
- 批次、站点、账号/域名及用户列表支持**列标题排序、搜索、筛选、分页和显示列**；行内操作仍使用原来的业务流程。窄屏表格可在自身区域横向滚动。
- **邮箱**保留邮箱/文件夹、邮件列表和纯文本阅读区，支持搜索、分页、已读/未读、监听、凭据、回复/回复全部/转发及附件。正文中的网址不会成为可点击链接，附件必须显式下载。发送、删除和显示密码前会确认；手机上通过返回按钮切换列表与阅读区。
- **表格**保留 Grist 组织/工作区/文档/页面选择、数据编辑、记录详情与附件。**设置**包含模型厂商、用途分配、商品资料 CJ、邮箱默认密码、Grist 和账户安全；密钥只显示尾号，厂商密钥相互独立，同一地址的已保存密钥留空不更换。
- 右下角 **pi 小助手**仍可查询业务、流式对话、停止、新建对话及处理服务端确认请求。页面校验错误直接显示在字段旁；操作结果通过通知提示。破坏性或外发操作使用确认窗口，放弃站点必须输入目标域名。

常用书签：`/`、`/new`、`/batches/:id`、`/sites/:id/overview`（以及 `chat`、`mail`、`changes`、`qa`）、`/accounts`、`/mail/:mailboxId/:folder/:uid`、`/tables`、`/settings`、`/users`。文件夹名中的空格等字符会编码到 URL。

## 1. 它能做什么

| 功能 | 说明 |
|---|---|
| 多账号管理 | 接入多个 Hostinger 账号，自动同步主机订单、网站、域名、邮箱订单，域名 30 天内到期会标出来 |
| 表单建站，可批量 | 填一次经营主体，再给每个域名填类目和数量，提交后全自动建站；一个批次可以有多个站，同时跑 3 个 |
| 18 步建站流水线 | 在 Hostinger 上建网站和 WordPress → 维护模式和 SSL → WooCommerce → 主题 → 伴侣插件 → 客服邮箱和邮件 DNS → 交易邮件 → CJ 选品 → AI 文案和政策 → 商店配置 → 页面 → 上架商品 → QA 验收 |
| 实时进度和日志 | 每一步的状态、耗时、说明，每次 Hostinger 调用和 AI 调用的记录；关掉窗口再打开也能看到完整历史 |
| 合规把关 | AI 只写文字，价格和运费由代码算；政策页必须写明真实的时效、运费、退货、退款；拦截编造的成立年份、认证、获奖、功效等说法 |
| QA 验收 | 16 项检查 + 浏览器截图 + 加购到结账；阻断项不过不算建完 |
| 一键上线 | 关维护模式、关 WooCommerce「即将上线」、允许搜索引擎收录，并以访客身份确认首页可见 |
| 和 pi 对话改内容 | 改标语、首页标题、关于我们、FAQ、政策页、公告栏、风格、商品名称和描述；每次修改都有快照，可以回滚，也可以定时恢复 |
| 客服邮箱 | 自动建 support@ 邮箱和 orders@ 别名；检查并修复 MX、SPF、DKIM、DMARC |
| 交易邮件 | WooCommerce 订单邮件经 support@ 的 SMTP 发出，发测试邮件并确认送达收件箱 |
| 邮箱中心 | 按域名集中查看所有账号的邮箱，实时收信、纯文本阅读、回复/转发和发送附件 |
| 放弃站点 | 经域名二次确认后，分步删除邮箱、别名和网站，关闭邮箱及域名自动续费，并保留可重试记录 |

**目前还不能做的**：在对话里改价格或做打折促销、改店铺规则（运费、时效、退货）、改菜单、换商品图片、临时下线后保留远端资源、连接支付（需要你本人登录 Stripe / PayPal 授权）、CSV 批量导入、保存经营主体模板。

## 2. 安装与首次启动

### 2.1 安装

1. 在项目目录运行 `npm run dist`，生成 `release/website-gen-setup-0.1.0.exe`（约 140 MB）。
2. 双击安装。安装包没有代码签名，Windows 会提示「Windows 已保护你的电脑」：点「更多信息」→「仍要运行」。
3. 按用户安装，不需要管理员权限，可以选择安装目录。装好后开始菜单和桌面有「独立站 AI 工厂」。

卸载：Windows「设置 → 应用 → 已安装的应用」里找「独立站 AI 工厂」。卸载不会删除你的数据（见第 10 节）。

### 2.2 窗口和托盘

- 左侧导航：**建站、批次、站点、账号、邮箱、设置**；顶部显示后台是否已连接、版本信息。邮箱旁的数字是当前工作区的未读总数。
- **关窗口不会退出**，只是缩到系统托盘，建站任务和定时恢复继续在后台跑。要真正退出，右键托盘图标 →「退出」；「显示主窗口」把窗口叫回来。
- 同一时间只能开一个实例，再次打开会切回已有窗口。

### 2.3 首次使用的三件事

按顺序做完这三件，才能开始建站：

1. **设置页 → 模型提供方**：给 DeepSeek 设置 API Key（见第 3 节）。
2. **设置页 → 商品资料**：设置 CJdropshipping API Key。
3. **账号页**：添加至少一个 Hostinger 账号（见第 4 节）。

## 3. 设置

### 3.1 模型提供方

预置了两个 DeepSeek 提供方：「OpenAI 格式」和「Anthropic 格式」。它们用同一个 Key，设置一个另一个也会更新。

- **设置 Key**：粘贴 DeepSeek 的 API Key → 保存。Key 加密保存在这台电脑上，保存后不再显示，只显示末 4 位。
- **测试**：发一个极短的请求，确认 Key 和地址可用；Key 不对会提示「Key 无效」。

### 3.2 用途

每个用途选一个提供方、模型和思考强度：

| 用途 | 现在用在哪里 | 默认 |
|---|---|---|
| 建站与对话 | 站点页和 pi 的对话 | deepseek-v4-pro，思考强度高 |
| 批量文案 | 建站时的选品筛查、站点文案、政策页、商品改写 | deepseek-flash，思考强度低 |
| 看截图 | 预留，暂未使用 | deepseek-flash |
| 合规审查 | 预留，暂未使用 | deepseek-v4-pro |

右侧显示每个用途是否可用；没设 Key 时显示原因。

### 3.3 商品资料（CJdropshipping）

在 CJ 后台「Authorization → API」生成 API Key，在这里点「设置 Key」。保存前会先向 CJ 验证，Key 不对不会保存。
CJ 只当**商品资料库**：读取标题、图片、规格、成本价，不授权店铺、不刊登、不下单。商品由你们自己供货发货。

### 3.4 邮箱的默认密码

建站时新建的 support@ 邮箱使用这个密码；保存或更换默认密码后，系统还会依次尝试登录所有尚未保存凭据的已有邮箱，并报告成功、失败和因连接问题稍后重试的数量。验证成功的邮箱会加密保存凭据、自动开启监听并开始建立邮件索引。错误密码只对同一个默认密码尝试一次；更换默认密码或在邮箱页点「用默认密码重试」后才会再试。连接超时等问题不会记成密码错误，会在下次同步时重试。

不设置时，新建邮箱使用独立随机强密码（更安全，可在站点页「显示」），已有邮箱则在邮箱页提示单独输入。默认密码至少 8 位，要有大写、小写、数字和特殊字符；加密保存，设置后不再显示。所有邮箱共用一个密码时，一个泄露就会影响全部使用它的邮箱。

## 4. 账号（Hostinger）

1. 在 hPanel 的「账户 → API」生成 Token。
2. 账号页点「**添加账号**」，填一个名称（例如「主账号」）和 API Token →「**验证并添加**」。Token 不对会被 Hostinger 直接拒绝，不会保存。
3. 添加后自动同步一次；之后每 30 分钟自动同步，也可以点「**同步**」手动刷新。

账号表显示每个账号的状态（正常 / Token 无效 / 同步出错）、订单、网站、域名、邮箱订单数量和上次同步时间。点账号名下面会列出它的域名：状态、到期日（30 天内到期标黄）、是否已建站、是否已开通邮箱。

「删除账号」只删除这台电脑上保存的 Token 和同步记录，Hostinger 上的网站、域名、邮箱都不受影响。

## 5. 建站

### 5.1 填写经营主体（本批次所有站共用）

| 字段 | 说明 |
|---|---|
| 主体类型 | 公司 / 个人经营者 |
| 公司法定名称（或经营者姓名） | 写进页脚、联系页、隐私政策和条款 |
| 地址 | 公开显示在页脚和联系页，也是退货地址；美国地址会自动拆进 WooCommerce 的店铺地址 |
| 客服电话 | 页脚和联系页显示 |
| 客服邮箱 | 默认勾选「使用各站自己的 support@域名」，系统会自动建这个邮箱；也可以改填一个已有邮箱 |
| 发货时效（工作日） | 处理 x–y 天，运输 x–y 天。**请填你们真实能做到的**：会原样写进运输政策和 FAQ，代码会核对 AI 写出来的天数（FTC 邮购规则要求有依据） |

### 5.2 填写站点（每行一个站）

| 字段 | 说明 |
|---|---|
| 域名 | 下拉里只有「已同步、在任何账号下都还没有网站、也没在别的批次里用过」的域名，后面标着所属账号 |
| 商品类目 | 英文关键词，可以填多个，用逗号分隔，例如 `dog beds, pet blankets`。系统用它在 CJ 搜商品，也用作商品分类名 |
| 商品数量 | 1–200，默认 20 |
| 售价区间（美元，可不填） | 填了就只上架售价落在区间内的商品和规格 |
| 品牌名（可不填） | 留空就用域名，例如 nordicpaws.com → Nordicpaws。之后可以让 pi 改 |

「添加一个站」加一行；行尾的垃圾桶删除一行。

### 5.3 提交

点「**开始建站**」：字段有问题会在对应位置标红；没问题会弹出确认框，列出要建站的域名和**政策页会写明的对买家的承诺**（时效、运费、退货、退款）。确认后自动跳到批次页。

### 5.4 店铺规则（所有站相同，由代码决定）

| 规则 | 内容 |
|---|---|
| 运费 | 满 $49 包邮，否则 $4.99 |
| 配送范围 | 美国本土 48 州 + 华盛顿特区 |
| 退货 | 收货 30 天内可退；质量问题由商家承担退货运费；不支持换货 |
| 退款 | 收到退货后 5–7 个工作日原路退款 |
| 定价 | 售价 = CJ 成本 × 2.5，取整后尾数 .99（毛利约 60%），AI 不参与 |
| 税 | 暂不收销售税 |
| 结账 | 允许游客结账 |

改这些规则需要改代码（`src/shared/rules.ts`），对话里改不了。

## 6. 批次：看进度、处理失败

### 6.1 页面结构

- **左侧**：批次列表，显示创建时间、站点数、完成数、失败数；有站在跑时带转圈图标。
- **右上**：所选批次的站点表：状态（排队中 / 进行中 / 等待 Hostinger / 已完成 / 失败 / 已上线）、进度条（x/18）、当前步骤、错误信息。
- **右下**：点一个站看详情：左边是 18 步时间线（每步的状态、耗时、说明），右边是日志。

### 6.2 18 个步骤

| # | 步骤 | 做什么 |
|---|---|---|
| 1 | 预检 | 确认域名在哪个账号下、实时确认它**没有网站**（已有网站的域名一律不覆盖）、选主机订单 |
| 2 | 创建网站 | 用 Hostinger 建网站并安装 WordPress，管理员密码随机生成、加密保存 |
| 3 | 安装 WordPress | 等安装完成（通常不到 1 分钟） |
| 4 | SSL 与维护模式 | 打开维护模式（访客看不到），确认 SSL 证书有效 |
| 5 | 安装 WooCommerce | |
| 6 | 卸载多余插件 | 卸载 Hostinger 默认装的 AI Assistant、Easy Onboarding、Reach（保留 Hostinger Tools） |
| 7 | 部署 Obel 主题 | 所有站共用一套主题 |
| 8 | 部署伴侣插件 | 站点伴侣插件让本工具能管理这个站 |
| 9 | 注册伴侣插件 | 用一次性令牌换取专用的应用密码，加密保存 |
| 10 | 客服邮箱 | 用域名的 Hostinger 邮箱订单建 support@（已有就复用）和 orders@ 别名 |
| 11 | 邮件 DNS | 检查并补齐 MX、SPF、DKIM、DMARC |
| 12 | 交易邮件发信 | 让订单邮件经 support@ 的 SMTP 发出，发测试邮件并确认送达 |
| 13 | 从 CJ 选品 | 按类目和售价区间搜商品，排除带电池、液体、儿童用品、仿牌等，再由 AI 筛查 |
| 14 | AI 撰写文案与政策 | 标语、首页、关于我们、8 条 FAQ、运输 / 退换货 / 隐私 / 条款 4 个政策页，代码逐项核对 |
| 15 | 配置商店 | 店名、标语、页脚联系方式、币种、运费、游客结账、风格，并设为不让搜索引擎收录 |
| 16 | 创建页面 | 首页、关于我们、联系我们、FAQ 和 4 个政策页 |
| 17 | 上架商品 | 逐个改写文案、按规则定价、建到 WooCommerce；失败的商品自动换下一个候选 |
| 18 | QA 验收 | 见 6.4 |

「等待 Hostinger」时不占名额；同时最多 3 个站在跑。电脑重启或应用退出后，再打开会从断点接着跑。

### 6.3 日志里能看到什么

每一步的开始和结束、每次 Hostinger 调用（操作名、耗时、成败，**从不记录参数和密码**）、AI 调用（任务、花费、开头一段输出）、警告（例如跳过某个商品的原因）和错误。

### 6.4 QA 报告

QA 跑完后，站点详情下方显示报告和截图（点截图放大）。

| 检查 | 级别 |
|---|---|
| 必需页面都已发布、首页 / 隐私页 / 联系方式已设置、政策页写明了运费 / 时效 / 退货 / 联系方式、商品有图有价格且在区间内、没有虚构或无法证实的宣传、运费设置、币种为美元、SSL 证书有效、页面能正常显示并能加购到结账 | **阻断**：不过就停下，站点标为失败 |
| 建站期间不让搜索引擎收录、商品数量达到目标、已连接支付方式、客服邮箱能收信、邮件 DNS、交易邮件经客服邮箱发出、商品图片版权 | **提醒**：不影响完成，但上线前应处理 |

截图在本机用 Edge 无界面打开：首页、商品列表、商品页、联系页、购物车、结账页、手机版首页。QA 用 Hostinger 的一次性登录链接以管理员身份查看（维护模式下也能看到真实页面），加购前后都会清空购物车。

### 6.5 失败了怎么办

- 网络超时这类临时错误会**自动重试**（最多 3 次，间隔 30 秒、60 秒…），日志里能看到「x 秒后自动重试」。
- 3 次都失败或遇到不能重试的错误（例如域名已有网站），站点标为**失败**，表格里显示原因。处理掉原因后点「**重试**」，从失败的那一步接着跑。

## 7. 上线

上线前建议先做完：

1. **看一遍网站**：QA 截图是真实页面；要自己浏览，先在 hPanel 里登录这个站的 WordPress 后台（维护模式下只有登录的管理员能看到真实页面）。
2. **连接支付**：在 WordPress 后台 → WooCommerce → 设置 → 支付，连接 Stripe 和 PayPal。这需要你本人登录授权，工具不能代办。没连接时顾客无法付款。
3. **换图片（建议）**：商品图片来自 CJ 的资料，正式上线前最好换成供应商授权或自己拍的图片。

然后在批次页的站点详情里点「**上线**」。确认框会列出 QA 还没解决的提醒。上线会依次：关闭 Hostinger 维护模式 → 关闭 WooCommerce 的「即将上线」→ 允许搜索引擎收录 → 以访客身份打开首页确认能看到。整个过程约半分钟；如果提示「访客暂时还看到维护页」，多半是缓存，几分钟后再看。重复点上线是安全的。

## 8. 站点：和 pi 对话改内容

站点页列出流程已全部完成的站（显示「已上线」或「维护模式中」）。选中一个站，中间是和 pi 的对话，右边是客服邮箱和变更记录。

### 8.1 怎么说

直接用中文说要改什么，例如：

- 「把顶部公告栏改成冬季上新的提示，12 月 1 日恢复」
- 「首页大标题写得更有温度一点」
- 「把 FAQ 里关于退货的回答写得更清楚」
- 「把 #123 号商品的标题改短一点」
- 「风格换成 editorial」

Enter 发送，Shift+Enter 换行；回复过程中可以点「**停止**」。「**新对话**」开始一段新的对话（旧对话保存在本机）。回复里能展开「思考过程」，也能看到 pi 调用了哪些工具、结果如何。

### 8.2 pi 能改什么

| 能改 | 不能改（对话里会说明原因） |
|---|---|
| 标语、首页大标题和副标题、关于我们、FAQ | 价格、打折、优惠券 |
| 运输 / 退换货 / 隐私 / 条款政策页（承诺的数字必须保持不变） | 运费、时效、退货期限、退款时效等店铺规则 |
| 顶部公告栏 | 菜单、图片、插件、主题文件 |
| 风格：default / editorial / dark | 网站以外的东西（域名、DNS、邮箱） |
| 商品名称、简短描述、详细描述 | |

所有修改和建站时一样经过检查：编造的成立年份、获奖、认证、功效，或者和店铺规则不一致的天数和金额，都会被拦下，pi 会改写后再试一次。**店里没有的折扣，pi 不会写进公告**（那是虚假宣传）。

修改**马上生效**。站点在维护模式下访客看不到；已上线的站，访客立刻能看到变化。

### 8.3 变更记录和回滚

每次修改记为一条变更：编号、说明、时间、发起方（pi / 你 / 定时恢复）、改了哪些内容。

- **回滚**：点「回滚」→ 确认，内容恢复成修改前的快照。如果同样的内容之后又被改过，会拒绝回滚，需要先回滚更晚的那条。
- **定时恢复**：让 pi 在某个时间自动回滚，例如「12 月 1 日恢复」。时间按这台电脑的本地时间。到点时应用要开着（关窗口在托盘里也行）；如果当时电脑关着，下次打开应用一分钟内补上。变更卡片上显示「将于 … 自动回滚」，可以点「取消」。

## 9. 客服邮箱与交易邮件

在站点页右侧「**客服邮箱**」面板（打开时会实时检查，几秒钟）。

### 9.1 邮箱和邮件 DNS

- 显示客服邮箱地址和状态（已开通 / 还没创建 / 没有邮箱订单）。
- 流水线新建的邮箱，密码加密保存在本机，点「**显示**」查看。复用的已有邮箱这里没有密码。
- MX、SPF、DKIM、DMARC 四项逐项显示对错（按公共 DNS 的结果，刚改的记录可能要几分钟才显示正确）。
- 有可以自动修的问题时出现「**修复**」：先列出要做的事（建邮箱、要写入的 DNS 记录），确认后执行。修复只补缺的：SPF 合并进原记录，不删其他 TXT 记录，**不改指向其他邮件服务的 MX**；Hostinger 会自动保存改动前的 DNS 快照，需要时可在 hPanel 恢复。
- 域名的 DNS 不在 Hostinger 时不能自动修，面板会列出需要你去 DNS 服务商那里添加的记录。
- 域名没有 Hostinger 邮箱订单时收不到邮件：在 hPanel 的「邮箱」里给这个域名开通**免费试用（1 个月）**，再点「重新检查」和「修复」。Hostinger 的 API 不能申请免费试用（只能买付费套餐），所以这一步要你在 hPanel 里点。
- 「修复」会一次做完：建 support@（用设置页的默认密码）和 orders@ 别名、补 DNS 记录、启用交易邮件并发测试邮件。

### 9.2 交易邮件

WooCommerce 的订单邮件默认用主机的发信方式，容易进垃圾箱。启用后改为经 support@ 的 SMTP（smtp.hostinger.com）发出，发件人显示店名。

- 流水线新建邮箱的站会**自动启用**，并发一封测试邮件、登录收件箱确认送达。
- 复用已有邮箱的站，面板会让你填这个邮箱的密码：「**验证并启用**」会先登录验证，对了才保存并启用。
- 不知道密码：「**不知道密码？生成新密码**」由应用生成新密码替换旧密码（确认后执行）。**其他地方用旧密码的登录会立即失效**，新密码在面板里「显示」查看。
- 已启用时可以填任意收件人「**发测试邮件**」；发给客服邮箱自己时会登录收件箱确认送达（最多等 90 秒）。
- 测试邮件发不出去时会自动关掉 SMTP，退回主机默认发信，保证订单邮件不会一封都发不出去。

### 9.3 邮箱中心：收信、阅读与发信

左侧「**邮箱**」页会列出所有已接入 Hostinger 账号的全部邮箱，并按域名分组。账号同步时会刷新，也可以在邮箱页手动点「同步」。桌面宽屏是邮箱 / 邮件列表 / 正文三栏；窄屏逐层进入。地址可以收藏，例如 `/mail/邮箱编号/INBOX/邮件UID`。

- **自动尝试默认密码**：流水线建出的邮箱直接使用已加密保存的密码；其他尚无凭据的邮箱会在清单同步时自动尝试设置页的默认密码。尝试中显示「正在用默认密码登录…」；密码被拒绝时才显示「需要密码」，可单独输入，或在更换默认密码后点「用默认密码重试」；没有设置默认密码时会明确提示去设置或单独输入。连接失败会等到下次同步重试，不会误报密码错误。验证成功后自动开启监听并开始索引。
- **查看或更换密码**：密码默认隐藏；需要更新其他客户端时，在「邮箱凭据」中明确点击「显示已保存密码」并确认，可沿用原有显示/隐藏密码流程。如果单独输入密码，应用会先用 IMAP 登录验证，再加密保存。如果选择重置，确认框会明确提醒：旧密码立即失效，其他客户端必须同步更新。
- **监听**：开启后优先保持 IMAP IDLE 实时连接。每个工作区最多 15 个同时 IDLE，其余邮箱每 2 分钟轮询。断线自动退避重连；关闭网页不会停止后台监听。新信会增加导航未读数并显示应用内通知。
- **阅读**：支持服务器列出的文件夹、发件人/主题搜索、分页、已读/未读和移到废纸篓。正文只显示纯文本，URL 只是不可点击的文字。
- **发信**：支持新邮件、回复、全部回复和转发；正文为纯文本。回复保留 `In-Reply-To` / `References` 并引用原文。附件总大小最多 20 MB。SMTP 发送成功后，应用会把副本补进已发送文件夹，并避免重复保存。
- **附件**：只在明确点击「下载」后请求，以强制下载方式返回，不在页面内预览。

**硬性安全边界**：应用不会访问邮件正文里的任何链接，不做链接预览，不加载远程图片、跟踪像素、CSS 或字体，也不解析远程 CID 资源。邮件 HTML 在服务端离线转换为纯文本，界面不渲染 HTML、链接或 iframe。

### 9.4 放弃站点

站点详情和账号的域名列表都有「**放弃这个站点**」。确认框会逐项列出后果，并要求完整输入域名。任务在后台执行，每一步都会重新读取 Hostinger 状态核验；失败会停在明确步骤，可以重试，不会猜测域名订阅。

1. 停止域名下所有邮箱监听，清除本工作区保存的邮箱凭据和邮件缓存。
2. 删除全部邮箱和别名；如果邮箱订单已经没有邮箱，关闭该邮箱订阅自动续费。
3. 删除网站（如果存在）。
4. 唯一识别域名订阅并关闭自动续费。注册域名不会立即删除，到期后自然失效；识别不唯一时任务停止。
5. 把站点标记为已放弃并保留历史；它从活跃列表隐藏，今后不会再出现在新批次的可用域名中，也不会恢复邮件监听。

单个邮箱也可以在邮箱页停止/开始监听或永久删除；删除前必须再次确认。

## 10. 数据与安全

- **数据目录**：`%APPDATA%\website-gen`（开发模式和安装版共用）：
  - `website-gen.sqlite`：账号、批次、站点、进度、日志、变更记录
  - `master.key`：主密钥，用 Windows 的数据保护（DPAPI）加密，只有当前 Windows 用户能解开
  - `pi\`：和 pi 的对话记录
  - `work\`：QA 截图、伴侣插件的临时副本
- **所有凭据**（Hostinger Token、DeepSeek Key、CJ Key、WordPress 管理员密码、伴侣插件应用密码、邮箱密码）都用主密钥加密保存，界面只显示末 4 位；日志里从不出现密码。
- **备份**：退出应用后复制整个 `website-gen` 目录。主密钥绑定当前 Windows 用户，**换电脑或换 Windows 用户后旧数据里的凭据解不开**，需要重新添加账号和 Key（导出主密钥的功能还没做）。
- **pi 的权限**：只能用上面列出的站点工具，不能读写电脑上的文件、不能执行命令。
- **伴侣插件**：只认本工具的专用账号 site-agent；站点上其他店长账号不能通过它改设置或发信服务器。

## 11. 常见问题

| 现象 | 原因和处理 |
|---|---|
| 添加账号提示「Token 无效」 | 在 hPanel 重新生成 Token；确认复制完整 |
| 账号状态「同步出错」或「无法解开保存的 Token」 | 前者看错误说明后点「同步」重试；后者说明数据来自另一台电脑或另一个 Windows 用户，删除账号后重新添加 |
| 建站页「没有可用的域名」 | 域名还没同步，或都已经有网站 / 在别的批次里。去账号页点「同步」 |
| 某一步失败，提示网络超时 | 会自动重试；本机用代理时偶尔会这样。3 次后仍失败就点「重试」 |
| 「预检」失败：已经有网站了 | 为了不覆盖已有网站，有网站的域名一律不建。换一个域名 |
| 「从 CJ 选品」失败：没找到商品 | 换一个更常见的英文类目关键词，或放宽 / 去掉售价区间 |
| QA 阻断项没过 | 看报告里的说明。截图能帮你判断页面问题；处理后点「重试」只重跑 QA |
| 「客服邮箱」跳过：没有邮箱订单 | 在 hPanel 的「邮箱」里给这个域名开通免费试用，然后在站点页点「修复」（会一并建邮箱、补 DNS、启用交易邮件） |
| 「交易邮件发信」跳过：没有密码 | 邮箱是之前就有的。在站点页填密码「验证并启用」，或「生成新密码」 |
| 测试邮件发出了但收件箱里没看到 | 可能延迟或进了垃圾箱；稍后再发一次，或在网页邮箱里查看垃圾箱 |
| 上线后访客还看到维护页 | 多半是缓存，几分钟后再看；仍然不行就再点一次上线 |
| pi 说某个改动做不了 | 价格、店铺规则、菜单、图片目前不能在对话里改 |
| 定时恢复失败 | 变更卡片上会显示原因，通常是那部分内容之后又被改过；先回滚更晚的变更，再手动回滚这一条 |
| 第一次运行 Windows 提示未知发布者 | 安装包没有代码签名；点「更多信息」→「仍要运行」 |
